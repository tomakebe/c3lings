# Глава 03. Управление потоком: сравнения, переходы, циклы

## Карта главы

**Что вы узнаете.**

* Что такое переход (`jmp`) и чем он отличается от `call`.
* Какие бывают метки в GNU as и какими пользоваться внутри функций.
* Как сравнивать (`cmp`, `test`) и как прыгать по результату сравнения
  (`je`, `jl`, `jb`, …).
* Главную ловушку главы: знаковые (`jl`/`jg`) против беззнаковых (`jb`/`ja`)

* Как переводить `if`/`else`, `&&`/`||`, `while`, `do-while`, `for`,
  `switch` в переходы.
* Как компилятор «переворачивает» циклы и чем ему помогает `cmov`.

**Зачем это нужно.** В ассемблере нет `if`, `while`, `for` и `switch`.
Есть одна идея: **флаги плюс условный переход**. Из неё собирается любая
управляющая конструкция. В этой главе мы научимся переводить структурный
код в переходы, узнаем, какие формы циклов предпочитают компиляторы, и
разберём одну из самых частых ошибок — путаницу знаковых и беззнаковых
сравнений.

**Что нужно знать заранее.** Главу 02: флаги ZF, SF, CF, OF и что их
ставит; `cmp` = вычитание ради флагов; `div` и подготовка `rdx`. Из главы
01 — порядок аргументов и ширину регистров.

**Упражнения:** `a0301`–`a0305`.

## 1. Безусловный переход и метки

### 1.1. `jmp`

Вспомните модель процессора из главы 00: он берёт инструкцию по адресу
`rip`, выполняет её и переходит к следующей. **Переход** (jump) —
инструкция, которая вместо «к следующей» отправляет `rip` в другое место.
Аналогия — фраза в книге-игре «перейдите к параграфу 42».

```asm
    jmp .Ldone          # rip = адрес метки .Ldone
    ...                 # эти строки будут пропущены
.Ldone:
```

`jmp` просто меняет `rip`. Варианты:

* `jmp метка` — прямой, адрес закодирован в инструкции (как смещение
  относительно `rip`; 2 байта для близких меток, 5 для дальних);
* `jmp rax` / `jmp [rax + 8]` — косвенный, адрес берётся из регистра
  или памяти (таблицы переходов, виртуальные вызовы, интерпретаторы).

Отличие от `call`: `jmp` никуда не записывает «откуда пришли», поэтому
вернуться по `ret` нельзя. `jmp` — это `goto`.

### 1.2. Метки в GNU as

| Вид | Пример | Область видимости |
|---|---|---|
| обычная | `loop:` | весь файл, попадает в таблицу символов |
| глобальная | `.globl f` + `f:` | видна линковщику |
| локальная `.L` | `.Lloop:` | файл, **не** попадает в объектник |
| числовая | `1:` / `jmp 1b` / `jmp 1f` | ближайшая назад/вперёд, можно повторять |

Внутри функций используйте `.L`-метки — они не засоряют вывод `objdump`
и `gdb`, а имена вроде `.Lsum_loop` делают код читаемым. Числовые метки
удобны для крошечных ветвлений на пару строк.

Важно: имя `.L`-метки должно быть уникальным **во всём файле**. Если в
одном `.s` две функции, и у обеих есть `.Lloop`, ассемблер скажет
`symbol '.Lloop' is already defined`. Добавляйте имя функции:
`.Lsum_loop`, `.Lgcd_loop`.

Числовые метки поясним примером:

```asm
    cmp edi, esi
    jg 1f           # 1f = "ближайшая метка 1: ВПЕРЁД (forward) по тексту"
    mov eax, esi
1:                  # <- сюда
    ret
```

> **Коротко:** `jmp` — это `goto`. Метки внутри функции — `.Lимя` (уникальные
> на файл) или числовые `1:` с `1f`/`1b`.

## 2. Сравнение: `cmp` и `test`

* `cmp a, b` — вычисляет `a - b` и выставляет флаги, результат выбрасывает.
* `test a, b` — вычисляет `a & b` и выставляет флаги (ZF, SF; CF = OF = 0).

Аналогия: `cmp` — это весы. Вы кладёте на них два груза, весы ничего не
меняют в грузах, а просто показывают стрелкой «левый тяжелее / равны /
правый тяжелее». Стрелка — это флаги. Читает стрелку следующая
инструкция — условный переход.

Идиомы:

```asm
test rdi, rdi      # rdi == 0? rdi < 0?  (короче, чем cmp rdi, 0)
test al, 1         # младший бит: чётность
test edi, 0x80     # проверка конкретного бита
cmp rdi, rsi       # сравнение двух чисел
cmp byte ptr [rdi], 0   # сравнение с памятью
```

Почему `test rdi, rdi` проверяет ноль и знак: `rdi & rdi = rdi`. Значит,
ZF = 1 ровно когда `rdi = 0`, а SF = старший бит `rdi`, то есть знак.

Почему `test al, 1` проверяет чётность: `al & 1` оставляет только младший
бит. У чётных чисел он 0 → ZF = 1. У нечётных он 1 → ZF = 0.

```
  13 = 0000 1101            12 = 0000 1100
&  1 = 0000 0001          &  1 = 0000 0001
     = 0000 0001  ZF=0         = 0000 0000  ZF=1  (чётное)
```

> **Коротко:** `cmp a, b` ≈ «сравнить a с b»; `test x, x` ≈ «x ноль? x
> отрицательный?»; `test x, маска` ≈ «есть ли эти биты?». Ни одна не меняет
> операнды.

## 3. Условные переходы

### 3.1. Как они работают

**Условный переход** (`jcc`, где `cc` — условие) смотрит на флаги: если
условие выполнено — прыгает на метку, если нет — выполнение просто идёт
на следующую строку.

После `cmp a, b`:

| Условие | Знаковое | Беззнаковое | Флаги |
|---|---|---|---|
| `a == b` | `je` / `jz` | `je` / `jz` | ZF = 1 |
| `a != b` | `jne` / `jnz` | `jne` / `jnz` | ZF = 0 |
| `a < b` | `jl` (`jnge`) | `jb` (`jc`, `jnae`) | SF≠OF / CF = 1 |
| `a <= b` | `jle` (`jng`) | `jbe` (`jna`) | ZF=1 или SF≠OF / CF=1 или ZF=1 |
| `a > b` | `jg` (`jnle`) | `ja` (`jnbe`) | ZF=0 и SF=OF / CF=0 и ZF=0 |
| `a >= b` | `jge` (`jnl`) | `jae` (`jnc`, `jnb`) | SF=OF / CF = 0 |

Флаговые переходы: `js`/`jns` (знак), `jo`/`jno` (переполнение),
`jc`/`jnc` (перенос), `jp`/`jnp` (чётность — нужен для сравнения float с
NaN, глава 09).

Расшифровка букв: `e` — equal, `n` — not, `z` — zero, `l` — less,
`g` — greater, `b` — below, `a` — above. `jnge` = «jump if not greater or
equal» — то же, что `jl`. Несколько имён — одна и та же машинная инструкция.

Мнемоника: **Greater/Less** — для знаковых (как «больше нуля» и «меньше
нуля»), **Above/Below** — для беззнаковых (как «выше/ниже» на шкале
адресов). Одна инструкция `cmp` — разная интерпретация в момент
перехода.

Правило чтения: `cmp a, b` + `jl X` читайте как «если **a** less **b** —
иди на X». Порядок такой же, как в записи `cmp`.

### 3.2. Почему «меньше» — это `SF ≠ OF`

Почему «меньше» для знаковых — это `SF ≠ OF`? Если вычитание не
переполнилось (OF = 0), знак разности честный: SF = 1 значит `a < b`.
Если переполнилось — знак перевёрнут. Отсюда XOR двух флагов.

Пример на 8 битах: `a = -128` (`0x80`), `b = 1`. Очевидно `a < b`.
`a - b = -129` — не помещается в 8 бит со знаком; в регистре окажется
`0x7F` = 127 (положительное!), SF = 0, но OF = 1. SF ≠ OF → «меньше»
— правильно. Если бы `jl` смотрел только на SF, он бы ошибся.

### 3.3. Знаковое против беззнакового: одна `cmp`, два ответа

Пусть `edi = 0xFFFFFFFF`, `esi = 2`, и выполнили `cmp edi, esi`.

| Интерпретация | `edi` | `esi` | Кто больше | `jg` | `ja` |
|---|---|---|---|---|---|
| знаковая (`int`) | −1 | 2 | `esi` | не прыгает | — |
| беззнаковая (`uint`) | 4294967295 | 2 | `edi` | — | прыгает |

Флаги после `cmp`: результат `0xFFFFFFFD`, ZF = 0, SF = 1, OF = 0, CF = 0
(заёма нет: 4294967295 ≥ 2). `jg` требует ZF=0 и SF=OF → 1 ≠ 0 → не
прыгает. `ja` требует CF=0 и ZF=0 → прыгает. Оба правы — каждый в своей
интерпретации.

### 3.4. Классическая ошибка

```c3
int x = -1;
uint limit = 10;
if (x < limit) ...     // C3 запретит такое сравнение без приведения — и правильно
```

Для процессора −1 — это `0xFFFFFFFF`. Сравните его через `jb` — и это
самое большое число, а не самое маленькое. Ошибка «перепутал `ja` и `jg`»
незаметна на положительных тестах и проявляется на отрицательных или
очень больших значениях. Именно её вы ищете в `a0301`.

Как выбирать: посмотрите на тип в `extern fn`. `int`, `long`, `ichar` →
`jl/jle/jg/jge`. `uint`, `ulong`, `char`, указатели, размеры → `jb/jbe/ja/jae`.

> **Коротко:** `cmp` одинаков для всех; знаковость выбирается буквой
> перехода: L/G — знаковые, B/A — беззнаковые. `je`/`jne` — для обоих.

> **Частые ошибки**
> * `ja` для `int` или `jg` для `uint` — ломается на отрицательных и на
>   числах ≥ `0x80000000`.
> * Перепутать порядок: `cmp a, b; jl` — это `a < b`, а не `b < a`.

## 4. От `if` к переходам

### 4.1. Схема `if/else`

```c3
if (x < 0) { A } else { B }
C
```

Компилятор инвертирует условие и прыгает *мимо* блока:

```asm
    test rdi, rdi
    jns .Lelse          # НЕ (x < 0) -> на else
    ...A...
    jmp .Lend           # обойти else
.Lelse:
    ...B...
.Lend:
    ...C...
```

Почему условие «инвертируют»? Переход умеет только одно: «если условие —
прыгни». Код блока A идёт сразу после проверки, поэтому выгодно
прыгать, когда A делать **не** надо. Схема-диаграмма:

```
          test
           |
     x>=0? |--- да ---------+
           | нет            |
           v                v
          [A]             [B]  .Lelse
           |                |
          jmp .Lend         |
           |                |
           +-----> [C] <----+  .Lend
```

### 4.2. Полный пример: модуль числа

`long abs(long x)`:

```asm
    .globl asm_abs
asm_abs:
    mov rax, rdi            # rax = x  (предполагаем, что x >= 0)
    test rax, rax           # SF = знак x
    jns .Labs_done          # x >= 0 -> ответ уже готов, прыгаем к ret
    neg rax                 # x < 0 -> rax = -x
.Labs_done:
    ret
```

Здесь `else`-ветки нет: мы заранее положили «ответ по умолчанию» и
исправляем его, только если нужно. Это частый приём.

| Шаг (x = −7) | `rax` | SF | Переход? |
|---|---|---|---|
| `mov rax, rdi` | −7 | ? | |
| `test rax, rax` | −7 | 1 | |
| `jns .Labs_done` | −7 | 1 | нет (SF = 1) |
| `neg rax` | 7 | 0 | |
| `ret` | 7 | | |

| Шаг (x = 7) | `rax` | SF | Переход? |
|---|---|---|---|
| `mov rax, rdi` | 7 | ? | |
| `test rax, rax` | 7 | 0 | |
| `jns .Labs_done` | 7 | 0 | **да** → сразу `ret` |

### 4.3. Fall-through — главная ловушка

Цепочки `else if` — та же схема, повторённая несколько раз. Главное
правило: **каждый блок заканчивается `jmp` или `ret`**, иначе исполнение
«провалится» в следующий блок (fall-through). В `a0302` пропущенный `ret`
— одна из ошибок.

Метка — это не стена, а просто имя адреса. Процессор не «видит» меток и
не останавливается на них. Если блок закончился, а `ret` нет, процессор
пойдёт выполнять следующую строку — даже если перед ней написано
`.Lzero:`.

```asm
.Lneg:
    mov rax, -1          # хотели вернуть -1...
                         # ...но ret нет, поэтому идём дальше:
.Lzero:
    xor eax, eax         # rax = 0 — результат -1 потерян!
    ret
```

### 4.4. `&&` и `||`

Логические `&&` и `||` превращаются в цепочки переходов с коротким
замыканием:

```asm
# if (a > 0 && b > 0) X
    test rdi, rdi
    jle .Lskip          # a <= 0 -> всё условие ложно, X не делаем
    test rsi, rsi
    jle .Lskip          # b <= 0 -> тоже ложно
    ...X...
.Lskip:
```

Для `||` логика зеркальная: первый же истинный операнд прыгает **на**
блок, а если все ложны — прыгаем мимо:

```asm
# if (a == 0 || b == 0) X
    test rdi, rdi
    jz .Ldo_x           # a == 0 -> условие истинно сразу
    test rsi, rsi
    jnz .Lskip          # b != 0 (и a != 0) -> ложно
.Ldo_x:
    ...X...
.Lskip:
```

**Короткое замыкание** — второе условие даже не проверяется, если
первое уже решило дело. Это то же, что делает C3.

### 4.5. Трюк: проверка диапазона одним сравнением

`if (lo <= x && x <= hi)` компиляторы превращают в

```asm
    lea eax, [rdi - lo]
    cmp eax, hi - lo
    jbe .Lin_range      # беззнаковое!
```

Если `x < lo`, разность «заворачивается» в огромное беззнаковое число и
проверка не проходит. Пригодится в главе 07 (`'a' <= c && c <= 'z'`).

Пример: «это цифра?» — `'0' = 48`, `'9' = 57`, проверяем `x - 48 <= 9`:

| `x` | `x - 48` (32 бита) | беззнаково | `<= 9`? |
|---|---|---|---|
| `'5'` (53) | 5 | 5 | да |
| `'a'` (97) | 49 | 49 | нет |
| `' '` (32) | −16 = `0xFFFFFFF0` | 4294967280 | нет |

Одно сравнение отсекло и «слишком маленькие», и «слишком большие».

> **Коротко:** `if` = проверка + переход **мимо** блока при ложном условии.
> Каждый блок заканчивается `jmp` или `ret`. `&&`/`||` — цепочки переходов.

> **Частые ошибки**
> * Забыли `ret`/`jmp` в конце ветки — провалились в следующую.
> * Инвертировали условие неправильно: «не `<`» — это `>=` (`jge`/`jae`),
>   а не `>`.

## 5. Циклы

Цикла как отдельной инструкции нет: цикл — это переход **назад**, на
метку выше по тексту.

### 5.1. while: проверка в начале

```asm
.Ltop:
    cmp rcx, rsi
    jae .Lend           # условие выхода
    ...тело...
    inc rcx
    jmp .Ltop
.Lend:
```

На каждой итерации — два перехода (`jae` и `jmp`).

### 5.2. do-while: проверка в конце

```asm
.Lloop:
    ...тело...
    dec rcx
    jnz .Lloop          # dec уже выставил ZF — cmp не нужен
```

Один переход на итерацию. Поэтому компиляторы почти всегда переписывают
`while` и `for` в форму «проверка перед циклом + do-while» (loop
rotation):

```asm
    test rsi, rsi
    jz .Lend            # ноль итераций?
.Lloop:
    ...тело...
    inc rcx
    cmp rcx, rsi
    jb .Lloop
.Lend:
```

Разница между while и do-while: do-while выполняет тело **хотя бы
раз**. Поэтому перед ним ставят проверку «а нужно ли вообще входить?».

### 5.3. Полный пример с трассировкой: степень числа

`long pow(long x, long n)` — `x` в степени `n` повторным умножением:

```asm
    .globl asm_pow
asm_pow:
    mov eax, 1              # rax = 1 (результат; запись в eax обнулит верх)
    mov rcx, rsi            # rcx = n (счётчик оставшихся умножений)
    test rcx, rcx           # n == 0?
    jz .Lpow_done           # да -> сразу вернуть 1
.Lpow_loop:
    imul rax, rdi           # rax *= x
    dec rcx                 # rcx -= 1, ZF = (rcx == 0)
    jnz .Lpow_loop          # ещё не ноль -> повторить
.Lpow_done:
    ret
```

Трассировка `pow(3, 4)`:

| Шаг | Инструкция | `rax` | `rcx` | ZF | Куда дальше |
|---|---|---|---|---|---|
| 1 | `mov eax, 1` | 1 | ? | | |
| 2 | `mov rcx, rsi` | 1 | 4 | | |
| 3 | `test rcx, rcx` | 1 | 4 | 0 | |
| 4 | `jz` | 1 | 4 | 0 | не прыгаем |
| 5 | `imul` | 3 | 4 | | |
| 6 | `dec` | 3 | 3 | 0 | |
| 7 | `jnz` | 3 | 3 | 0 | назад на `.Lpow_loop` |
| 8–10 | `imul`/`dec`/`jnz` | 9 | 2 | 0 | назад |
| 11–13 | `imul`/`dec`/`jnz` | 27 | 1 | 0 | назад |
| 14–16 | `imul`/`dec`/`jnz` | 81 | 0 | **1** | вперёд, к `ret` |

Тело выполнилось ровно 4 раза. Для `pow(5, 0)` строки 3–4 сразу
отправят нас на `ret` с `rax = 1`. Без этой проверки `dec` от 0 дал бы
−1, и цикл крутился бы 2⁶⁴ раз.

Как проверить «на одну итерацию больше/меньше»: прогоните в голове
самые маленькие случаи — `n = 0`, `n = 1`, `n = 2`. Ошибки на единицу
(off-by-one) почти всегда видны именно там.

### 5.4. Счёт вниз к нулю

Если направление не важно, считать вниз выгоднее: `dec rcx; jnz` — флаг
нуля ставится бесплатно. Счёт вверх требует `cmp` с границей.
Современные процессоры умеют склеивать `cmp`+`jcc` и `dec`+`jnz` в одну
микрооперацию (macro-fusion), так что разница небольшая — но вы будете
часто видеть оба варианта.

**Микрооперация** (µop) — элементарный внутренний шаг процессора; сложная
инструкция может распадаться на несколько, а пара простых — склеиваться
в одну.

### 5.5. Вложенные циклы

Вложенный цикл — это цикл, внутри тела которого целиком лежит другой
цикл. В ассемблере это просто две пары меток, одна внутри другой.
Главное — **у каждого цикла свои регистры**: внешний счётчик не должен
портиться внутренним циклом.

```asm
    mov r8, 0               # i = 0 (внешний счётчик)
.Louter:
    mov r9, 0               # j = 0 (внутренний счётчик, сбрасываем каждый раз!)
.Linner:
    ...тело, видит r8 и r9...
    inc r9
    cmp r9, rsi
    jb .Linner              # j < m -> ещё круг внутреннего
    inc r8
    cmp r8, rdi
    jb .Louter              # i < n -> ещё круг внешнего
```

Перед кодом удобно выписать таблицу «регистр → роль», например:
`r8` — i, `r9` — j, `rax` — результат, `rdx` — испортится делением. И
сверяться с ней, когда пишете тело.

### 5.6. Инструкция `loop`

`loop .Lx` = «`dec rcx`, и если не ноль — переход», без изменения флагов.
Выглядит идеально, но на большинстве CPU Intel она медленнее пары
`dec`/`jnz`, поэтому компиляторы её не генерируют. Знать стоит — писать
не стоит.

> **Коротко:** цикл = переход назад. Удобная форма — «проверка перед
> входом + do-while с проверкой в конце». `dec` ставит ZF — `cmp` с нулём
> не нужен. Всегда проверяйте `n = 0` и `n = 1`.

> **Частые ошибки**
> * Off-by-one: условие выхода проверяет «на одну итерацию раньше».
> * Цикл с `dec` без проверки на ноль до входа — бесконечный цикл (код 124).
> * Внутренний цикл портит регистр внешнего.
> * Забыли обнулить `rdx` перед **каждым** `div` в цикле — после первого
>   деления там остаток.

## 6. switch и таблицы переходов

Плотный `switch` компилятор превращает в **таблицу переходов**:
массив адресов (или смещений) и косвенный `jmp`. Вот что c3c `-O1`
сделал из `switch (op)` с пятью случаями:

```asm
    cmp edi, 4
    ja .Ldefault                    # беззнаковое: заодно ловит op < 0
    mov ecx, edi
    lea rdx, [rip + .Ltable]
    movsxd rcx, dword ptr [rdx + rcx*4]   # 32-битное смещение из таблицы
    add rcx, rdx                    # + адрес таблицы
    jmp rcx                         # косвенный переход
```

Аналогия: вместо цепочки «если 0 — туда, если 1 — сюда, если 2 — …»
компилятор строит оглавление. Номер случая — это номер строки в
оглавлении, а в строке записано, куда идти. Одно чтение + один прыжок,
сколько бы случаев ни было.

В PIE-коде таблица хранит не абсолютные адреса, а смещения относительно
самой таблицы — поэтому `movsxd` и `add`. Заметьте трюк с `ja`: один
беззнаковый переход проверяет и `op > 4`, и `op < 0`.

**PIE** (position-independent executable) — программа, которую ОС может
загрузить по любому адресу. Поэтому в коде нельзя «зашивать» абсолютные
адреса — только расстояния от текущего места.

Разреженный `switch` (значения 1, 1000, 50000) превращается в цепочку
сравнений или двоичный поиск.

## 7. Как это делает компилятор

```c3
fn int imax(int a, int b) { if (a > b) return a; return b; }
fn ulong count_digits(ulong n) { ulong c = 0; do { n /= 10; c++; } while (n != 0); return c; }
```

c3c `-O1`:

```asm
imax:
    mov eax, esi            # ответ по умолчанию: b
    cmp edi, esi            # сравнить a и b
    cmovg eax, edi          # условное копирование вместо перехода!
    ret

count_digits:
    xor ecx, ecx                      # c = 0
    movabs rsi, 0xCCCCCCCCCCCCCCCD    # «магическое» число для деления на 10
.L1:
    mov rax, rdi                      # rax = n
    mul rsi                           # rdx:rax = n * магия
    shr rdx, 3              # rdx = n / 10 (деление через умножение, глава 02)
    inc rcx                           # c++
    cmp rdi, 9              # старое n > 9  <=>  новое n != 0
    mov rdi, rdx                      # n = n / 10 (mov не трогает флаги)
    ja .L1                            # беззнаковое «больше»
    mov rax, rcx
    ret
```

Сразу три урока:

* для простого `max` компилятор вообще не делает переход — `cmov`
  (глава 13) не страдает от ошибок предсказания;
* условие цикла переписано: вместо «новое n ≠ 0» проверяется «старое
  n > 9», чтобы сравнение не ждало результата умножения;
* `mov` между `cmp` и `ja` — можно, `mov` не трогает флаги.

`cmovg eax, edi` читается как «если по флагам вышло greater — скопировать
`edi` в `eax`, иначе ничего не делать». Перехода нет — процессору не
нужно угадывать, куда пойдёт выполнение. (**Предсказание переходов** —
процессор заранее угадывает, прыгнет ли `jcc`, и начинает выполнять код
«наугад»; если не угадал — теряет 15–20 тактов. Подробно — главы 13–14.)

(На `-O1` c3c ещё оставляет `push rbp; mov rbp, rsp` — кадр стека для
отладчика; глава 06.)

## 8. Отладка ветвлений в gdb

```
(gdb) break asm_max
(gdb) run
(gdb) stepi
(gdb) info registers eflags      # покажет [ ZF SF CF ... ] — какие флаги стоят
(gdb) p $eflags
```

`info registers eflags` выводит установленные флаги по именам — очень
удобно, чтобы понять, почему `jl` не прыгнул.

Например, после `cmp edi, esi` с `edi = -5` (`0xFFFFFFFB`), `esi = 2`
вы увидите `[ PF SF IF ]`. В списке — только флаги, равные 1. Читаем:

* SF = 1, OF = 0 (его нет в списке) → SF ≠ OF → `jl` прыгнет: −5 < 2
  в знаковом смысле;
* CF = 0 (его нет в списке) → `jb` **не** прыгнет: беззнаково
  `0xFFFFFFFB` = 4294967291 ≥ 2.

(`IF` — флаг разрешения прерываний, он стоит всегда, не обращайте
внимания; `PF` нам не нужен.)

## 9. Подводные камни

> **Частые ошибки**
>
> * **`ja`/`jb` для знаковых, `jg`/`jl` для беззнаковых.**
> * **Перевёрнутое условие.** `cmp a, b; jl X` — прыгает, если `a < b`, а не
>   `b < a`. Читайте как «a jl b».
> * **Сравнение не той ширины.** `test edi, edi` для `long` сочтёт
>   `0x1_0000_0000` нулём, а положительное `0x8000_0000` — отрицательным:
>   флаги считаются по младшим 32 битам.
> * **Fall-through.** Забыли `jmp`/`ret` в конце ветки.
> * **Флаги испорчены между `cmp` и `jcc`.** `add`, `xor`, `inc`, `sub` —
>   портят; `mov`, `lea` — нет.
> * **Бесконечный цикл**, когда счётчик проходит мимо условия (`dec` от 0
>   даёт −1, а `jnz` продолжит ещё 2⁶⁴ раз). Проверяйте граничный случай
>   `n = 0` до входа в цикл.
> * **Две одинаковые `.L`-метки в одном файле** — ошибка ассемблера.

## Как это связано с упражнениями

* **`a0301` max** — максимум двух `int` и двух `uint`; переходы
  перепутаны местами. Разделы 3.1, 3.3, 3.4. Посмотрите на типы в
  `extern fn` и выберите букву перехода. Тесты специально используют −5
  и `0xFFFFFFFF`.
* **`a0302` sign** — `sign(x)` (−1/0/1) и `clamp(x, lo, hi)`. Разделы 2
  (`test`), 4.1–4.3 (ветвления и fall-through). В `asm_sign` две ошибки:
  ширина (`x` — `long`, см. 3.4 главы 02) и пропущенный конец ветки.
  Для `clamp` удобен приём «ответ по умолчанию» из 4.2; все числа знаковые.
* **`a0303` loops** — найти ошибку в `sum_to` и написать `count_digits`.
  Раздел 5 (особенно 5.3 — прогон для маленьких `n`). Для `sum_to`
  проследите таблицей `n = 1` и `n = 2`. Для `count_digits` вспомните,
  что у нуля одна цифра (значит — do-while), и про подготовку `rdx`
  перед каждым `div` (глава 02, раздел 6).
* **`a0304` gcd** — алгоритм Евклида и НОК. Разделы 5.1 (while) и `div`.
  Внимание: остаток — в `rdx`; `b` пришёл в `rsi`, а не в `rdx`, так что
  деление его не испортит, но подумайте, в каком порядке переставлять
  значения. Для НОК — делите до умножения, как сказано в шапке.
* **`a0305` collatz** — число шагов и вложенный цикл поиска максимума.
  Разделы 5.3 и 5.5. Выпишите таблицу «регистр → роль» до того, как
  начнёте писать; помните, что `div` здесь не нужен (в шапке даны
  `test`, `shr`, `lea`), и что при равенстве шагов обновлять ответ не нужно
  (подумайте, какой переход — строгий или нестрогий).

## Словарик

| Термин | Простыми словами |
|---|---|
| **переход (jump)** | инструкция, меняющая `rip`: «дальше выполняй вон там» |
| **`jmp`** | безусловный переход, аналог `goto` |
| **условный переход (`jcc`)** | прыгает, только если флаги удовлетворяют условию |
| **прямой / косвенный переход** | адрес в самой инструкции / в регистре или памяти |
| **метка `.L`** | локальное имя адреса, не попадает в объектник; уникально в файле |
| **числовая метка** | `1:`, на неё ссылаются `1f` (вперёд) и `1b` (назад) |
| **`cmp` / `test`** | вычитание / побитовое И только ради флагов |
| **less/greater** | знаковые сравнения (`jl`, `jg`, …) |
| **below/above** | беззнаковые сравнения (`jb`, `ja`, …) |
| **fall-through** | «проваливание» в следующий блок, если нет `jmp`/`ret` |
| **короткое замыкание** | второе условие в `&&`/`||` не проверяется, если ответ уже ясен |
| **loop rotation** | переделка `while` в «проверка + do-while» ради одного перехода на итерацию |
| **off-by-one** | ошибка «на единицу»: на одну итерацию больше или меньше |
| **таблица переходов** | массив адресов/смещений для `switch` + косвенный `jmp` |
| **PIE** | программа, загружаемая по любому адресу; адреса считаются от `rip` |
| **`cmov`** | условное копирование без перехода |
| **предсказание переходов** | процессор угадывает исход `jcc` заранее; промах стоит десятки тактов |
| **macro-fusion** | склейка `cmp`+`jcc` в одну микрооперацию |
| **микрооперация (µop)** | элементарный внутренний шаг процессора |
