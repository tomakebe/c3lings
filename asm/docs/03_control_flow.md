# Глава 03. Управление потоком: сравнения, переходы, циклы

В ассемблере нет `if`, `while`, `for` и `switch`. Есть одна идея: **флаги
плюс условный переход**. Из неё собирается любая управляющая конструкция.
В этой главе мы научимся переводить структурный код в переходы, узнаем,
какие формы циклов предпочитают компиляторы, и разберём одну из самых
частых ошибок — путаницу знаковых и беззнаковых сравнений.

Упражнения: `a0301`–`a0305`.

## 1. Безусловный переход и метки

```asm
    jmp .Ldone          # rip = адрес метки .Ldone
    ...
.Ldone:
```

`jmp` просто меняет `rip`. Варианты:

* `jmp метка` — прямой, адрес закодирован в инструкции (как смещение
  относительно `rip`; 2 байта для близких меток, 5 для дальних);
* `jmp rax` / `jmp [rax + 8]` — косвенный, адрес берётся из регистра
  или памяти (таблицы переходов, виртуальные вызовы, интерпретаторы).

### Метки в GNU as

| Вид | Пример | Область видимости |
|---|---|---|
| обычная | `loop:` | весь файл, попадает в таблицу символов |
| глобальная | `.globl f` + `f:` | видна линковщику |
| локальная `.L` | `.Lloop:` | файл, **не** попадает в объектник |
| числовая | `1:` / `jmp 1b` / `jmp 1f` | ближайшая назад/вперёд, можно повторять |

Внутри функций используйте `.L`-метки — они не засоряют вывод `objdump`
и `gdb`, а имена вроде `.Lsum_loop` делают код читаемым. Числовые метки
удобны для крошечных ветвлений на пару строк.

## 2. Сравнение: `cmp` и `test`

* `cmp a, b` — вычисляет `a - b` и выставляет флаги, результат выбрасывает.
* `test a, b` — вычисляет `a & b` и выставляет флаги (ZF, SF; CF = OF = 0).

Идиомы:

```asm
test rdi, rdi      # rdi == 0? rdi < 0?  (короче, чем cmp rdi, 0)
test al, 1         # младший бит: чётность
test edi, 0x80     # проверка конкретного бита
cmp rdi, rsi       # сравнение двух чисел
cmp byte ptr [rdi], 0   # сравнение с памятью
```

## 3. Условные переходы

После `cmp a, b`:

| Условие | Знаковое | Беззнаковое | Флаги |
|---|---|---|---|
| `a == b` | `je` / `jz` | `je` / `jz` | ZF = 1 |
| `a != b` | `jne` / `jnz` | `jne` / `jnz` | ZF = 0 |
| `a < b` | `jl` (`jnge`) | `jb` (`jc`, `jnae`) | SF≠OF / CF = 1 |
| `a <= b` | `jle` (`jng`) | `jbe` (`jna`) | ZF=1 или SF≠OF / CF=1 или ZF=1 |
| `a > b` | `jg` (`jnle`) | `ja` (`jnbe`) | ZF=0 и SF=OF / CF=0 и ZF=0 |
| `a >= b` | `jge` (`jnl`) | `jae` (`jnc`, `jnb`) | SF=OF / CF = 0 |

Флаговые переходы: `js`/`jns` (знак), `jo`/`jno` (переполнение),
`jc`/`jnc` (перенос), `jp`/`jnp` (чётность — нужен для сравнения float с
NaN, глава 09).

Мнемоника: **Greater/Less** — для знаковых (как «больше нуля» и «меньше
нуля»), **Above/Below** — для беззнаковых (как «выше/ниже» на шкале
адресов). Одна инструкция `cmp` — разная интерпретация в момент
перехода.

Почему «меньше» для знаковых — это `SF ≠ OF`? Если вычитание не
переполнилось (OF = 0), знак разности честный: SF = 1 значит `a < b`.
Если переполнилось — знак перевёрнут. Отсюда XOR двух флагов.

### Классическая ошибка

```c3
int x = -1;
uint limit = 10;
if (x < limit) ...     // C3 запретит такое сравнение без приведения — и правильно
```

Для процессора −1 — это `0xFFFFFFFF`. Сравните его через `jb` — и это
самое большое число, а не самое маленькое. Ошибка «перепутал `ja` и `jg`»
незаметна на положительных тестах и проявляется на отрицательных или
очень больших значениях. Именно её вы ищете в `a0301`.

## 4. От `if` к переходам

```c3
if (x < 0) { A } else { B }
C
```

Компилятор инвертирует условие и прыгает *мимо* блока:

```asm
    test rdi, rdi
    jns .Lelse          # НЕ (x < 0) -> на else
    ...A...
    jmp .Lend           # обойти else
.Lelse:
    ...B...
.Lend:
    ...C...
```

Цепочки `else if` — та же схема, повторённая несколько раз. Главное
правило: **каждый блок заканчивается `jmp` или `ret`**, иначе исполнение
«провалится» в следующий блок (fall-through). В `a0302` пропущенный `ret`
— одна из ошибок.

Логические `&&` и `||` превращаются в цепочки переходов с коротким
замыканием:

```asm
# if (a > 0 && b > 0) X
    test rdi, rdi
    jle .Lskip
    test rsi, rsi
    jle .Lskip
    ...X...
.Lskip:
```

### Трюк: проверка диапазона одним сравнением

`if (lo <= x && x <= hi)` компиляторы превращают в

```asm
    lea eax, [rdi - lo]
    cmp eax, hi - lo
    jbe .Lin_range      # беззнаковое!
```

Если `x < lo`, разность «заворачивается» в огромное беззнаковое число и
проверка не проходит. Пригодится в главе 07 (`'a' <= c && c <= 'z'`).

## 5. Циклы

### while: проверка в начале

```asm
.Ltop:
    cmp rcx, rsi
    jae .Lend           # условие выхода
    ...тело...
    inc rcx
    jmp .Ltop
.Lend:
```

На каждой итерации — два перехода (`jae` и `jmp`).

### do-while: проверка в конце

```asm
.Lloop:
    ...тело...
    dec rcx
    jnz .Lloop          # dec уже выставил ZF — cmp не нужен
```

Один переход на итерацию. Поэтому компиляторы почти всегда переписывают
`while` и `for` в форму «проверка перед циклом + do-while» (loop
rotation):

```asm
    test rsi, rsi
    jz .Lend            # ноль итераций?
.Lloop:
    ...тело...
    inc rcx
    cmp rcx, rsi
    jb .Lloop
.Lend:
```

### Счёт вниз к нулю

Если направление не важно, считать вниз выгоднее: `dec rcx; jnz` — флаг
нуля ставится бесплатно. Счёт вверх требует `cmp` с границей.
Современные процессоры умеют склеивать `cmp`+`jcc` и `dec`+`jnz` в одну
микрооперацию (macro-fusion), так что разница небольшая — но вы будете
часто видеть оба варианта.

### Инструкция `loop`

`loop .Lx` = «`dec rcx`, и если не ноль — переход», без изменения флагов.
Выглядит идеально, но на большинстве CPU Intel она медленнее пары
`dec`/`jnz`, поэтому компиляторы её не генерируют. Знать стоит — писать
не стоит.

## 6. switch и таблицы переходов

Плотный `switch` компилятор превращает в **таблицу переходов**:
массив адресов (или смещений) и косвенный `jmp`. Вот что c3c `-O1`
сделал из `switch (op)` с пятью случаями:

```asm
    cmp edi, 4
    ja .Ldefault                    # беззнаковое: заодно ловит op < 0
    mov ecx, edi
    lea rdx, [rip + .Ltable]
    movsxd rcx, dword ptr [rdx + rcx*4]   # 32-битное смещение из таблицы
    add rcx, rdx                    # + адрес таблицы
    jmp rcx                         # косвенный переход
```

В PIE-коде таблица хранит не абсолютные адреса, а смещения относительно
самой таблицы — поэтому `movsxd` и `add`. Заметьте трюк с `ja`: один
беззнаковый переход проверяет и `op > 4`, и `op < 0`.

Разреженный `switch` (значения 1, 1000, 50000) превращается в цепочку
сравнений или двоичный поиск.

## 7. Как это делает компилятор

```c3
fn int imax(int a, int b) { if (a > b) return a; return b; }
fn ulong count_digits(ulong n) { ulong c = 0; do { n /= 10; c++; } while (n != 0); return c; }
```

c3c `-O1`:

```asm
imax:
    mov eax, esi
    cmp edi, esi
    cmovg eax, edi          # условное копирование вместо перехода!
    ret

count_digits:
    xor ecx, ecx
    movabs rsi, 0xCCCCCCCCCCCCCCCD
.L1:
    mov rax, rdi
    mul rsi
    shr rdx, 3              # rdx = n / 10 (деление через умножение, глава 02)
    inc rcx
    cmp rdi, 9              # старое n > 9  <=>  новое n != 0
    mov rdi, rdx
    ja .L1
    mov rax, rcx
    ret
```

Сразу три урока:

* для простого `max` компилятор вообще не делает переход — `cmov`
  (глава 13) не страдает от ошибок предсказания;
* условие цикла переписано: вместо «новое n ≠ 0» проверяется «старое
  n > 9», чтобы сравнение не ждало результата умножения;
* `mov` между `cmp` и `ja` — можно, `mov` не трогает флаги.

(На `-O1` c3c ещё оставляет `push rbp; mov rbp, rsp` — кадр стека для
отладчика; глава 06.)

## 8. Отладка ветвлений в gdb

```
(gdb) break asm_max
(gdb) run
(gdb) stepi
(gdb) info registers eflags      # покажет [ ZF SF CF ... ] — какие флаги стоят
(gdb) p $eflags
```

`info registers eflags` выводит установленные флаги по именам — очень
удобно, чтобы понять, почему `jl` не прыгнул.

## 9. Подводные камни

* **`ja`/`jb` для знаковых, `jg`/`jl` для беззнаковых.**
* **Перевёрнутое условие.** `cmp a, b; jl X` — прыгает, если `a < b`, а не
  `b < a`. Читайте как «a jl b».
* **Сравнение не той ширины.** `test edi, edi` для `long` сочтёт
  `0x1_0000_0000` нулём, а положительное `0x8000_0000` — отрицательным:
  флаги считаются по младшим 32 битам.
* **Fall-through.** Забыли `jmp`/`ret` в конце ветки.
* **Флаги испорчены между `cmp` и `jcc`.** `add`, `xor`, `inc`, `sub` —
  портят; `mov`, `lea` — нет.
* **Бесконечный цикл**, когда счётчик проходит мимо условия (`dec` от 0
  даёт −1, а `jnz` продолжит ещё 2⁶⁴ раз). Проверяйте граничный случай
  `n = 0` до входа в цикл.
