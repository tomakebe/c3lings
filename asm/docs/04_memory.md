# Глава 04. Адресация памяти, массивы и `lea`

## Карта главы

**Что вы узнаете.**

* Как читать и писать память: квадратные скобки, размер обращения
  (`byte ptr`, `dword ptr`, …).
* Единую для x86 форму адреса `[base + index*scale + disp]` и как через
  неё выражаются `*p`, `a[i]`, `s->field`, `a[i].field`.
* Как загружать из памяти маленькие типы с расширением (`movzx`/`movsx`
  с памятью).
* Как объявлять глобальные данные в `.s`-файле и обращаться к ним через
  `rip` (RIP-relative адресация).
* Инструкцию `lea` — «вычислить адрес, но не читать» — и почему это
  самый популярный калькулятор в коде компиляторов.
* Два стиля обхода массива: индекс и бегущий указатель.
* Что такое выравнивание и зачем оно.

**Зачем это нужно.** До сих пор всё жило в регистрах. Но регистров
шестнадцать, а данных — гигабайты. В этой главе мы научимся читать и
писать память, разберём единый для x86 режим адресации
`[base + index*scale + disp]` и узнаем, почему инструкция `lea`,
«загрузить адрес», на деле — самый популярный калькулятор в коде,
который генерируют компиляторы.

**Что нужно знать заранее.** Глава 00 (память — массив байтов,
little-endian), глава 01 (`movzx`/`movsx`, окна регистров), глава 03
(циклы, беззнаковые сравнения `jb`/`jae`). Из C3 — указатели, массивы,
`&a[i]`, `sizeof`.

**Упражнения:** `a0401`–`a0405`.

| Упражнение | Разделы |
|---|---|
| `a0401` index | 1, 2 |
| `a0402` sum | 2.3, 2.4, 5 |
| `a0403` lea | 4 |
| `a0404` histogram | 2.3, 2.4 |
| `a0405` reverse | 2, 5 |

## 1. Операнд в памяти

### 1.1. Идея

Вспомните: память — это огромный массив байтов, адрес — номер байта.
Указатель в C3 — это просто число-адрес. В ассемблере, чтобы сказать
«не само число из `rdi`, а то, что лежит в памяти по адресу `rdi`»,
используют **квадратные скобки**: `[rdi]`. Это ровно разыменование
`*p` в C3.

Аналогия: `rdi` — номер ячейки в камере хранения. `rdi` без скобок — это
бумажка с номером. `[rdi]` — содержимое ячейки с этим номером.

### 1.2. Примеры

Квадратные скобки — обращение к памяти по адресу:

```asm
mov rax, [rdi]          # rax = 8 байт по адресу rdi    (*(long*)p)
mov eax, [rdi]          # eax = 4 байта                  (*(int*)p)
mov [rdi], esi          # 4 байта по адресу rdi = esi    (*(int*)p = x)
add rax, [rdi + 8]      # прибавить 8 байт из памяти
inc dword ptr [rdi]     # (*(int*)p)++  — чтение, изменение, запись
```

**Чтение** (load) — память в приёмник-регистр: `mov eax, [rdi]`.
**Запись** (store) — регистр в память: `mov [rdi], esi`. Порядок тот же,
что всегда: приёмник слева.

Почти любая арифметическая инструкция x86 принимает один операнд из
памяти — это CISC-наследие, и оно удобно. Ограничение: **не более одного
операнда в памяти** на инструкцию (кроме специальных вроде `movs`).
`mov [rdi], [rsi]` не существует.

(**CISC** — «сложный набор команд»: одна инструкция может и прочитать
память, и посчитать, и записать. Противоположность — RISC, например ARM,
где с памятью работают только отдельные `load`/`store`.)

Чтобы скопировать из памяти в память, — два шага через регистр:

```asm
mov eax, [rsi]          # прочитать *src во временный регистр
mov [rdi], eax          # записать в *dst
```

> **Коротко:** `[адрес]` — это «память по адресу», как `*p`. В одной
> инструкции — не больше одного операнда в памяти.

## 2. Режим адресации

### 2.1. Общая форма

Общая форма эффективного адреса:

```
[ base + index * scale + displacement ]
```

**Эффективный адрес** — итоговое число-адрес, которое процессор
вычисляет из этих частей перед обращением к памяти.

| Часть | Что может быть | Пример |
|---|---|---|
| base | любой 64-битный регистр | `rdi` |
| index | любой регистр, кроме `rsp` | `rcx` |
| scale | 1, 2, 4 или 8 | `4` |
| displacement | знаковое 32-битное число (или символ) | `16`, `-8`, `label` |

По-русски: **base** — база, «откуда начинаем» (обычно указатель на начало
массива или структуры); **index** — индекс, «какой по счёту элемент»;
**scale** — масштаб, «размер одного элемента в байтах»; **displacement**
(смещение) — постоянная добавка, «сколько байт отступить ещё».

Любую часть можно опустить. Примеры и их смысл в C:

| Адрес | Типичное значение |
|---|---|
| `[rdi]` | `*p` |
| `[rdi + 8]` | поле структуры по смещению 8; `p[1]` для `long*` |
| `[rdi + rcx*4]` | `a[i]` для `int` |
| `[rdi + rcx*8 + 16]` | `a[i + 2]` для `long` или `s->arr[i]`, где `arr` по смещению 16 |
| `[rbp - 24]` | локальная переменная (глава 06) |
| `[rip + table]` | глобальная переменная / константа (RIP-relative) |
| `[rcx*8 + 1000]` | без base — разрешено |

### 2.2. Почему `a[i]` — это `[a + i*4]`

Пусть `int[5] a = {10, 20, 30, 40, 50}` лежит в памяти с адреса `0x1000`.
Каждый `int` — 4 байта:

```
адрес:   0x1000      0x1004      0x1008      0x100C      0x1010
         +-----------+-----------+-----------+-----------+-----------+
         |    10     |    20     |    30     |    40     |    50     |
         +-----------+-----------+-----------+-----------+-----------+
индекс:     a[0]        a[1]        a[2]        a[3]        a[4]
```

Адрес `a[i]` = `0x1000 + i * 4`. При `rdi = 0x1000`, `rcx = 3`:

```
[rdi + rcx*4] = 0x1000 + 3*4 = 0x100C  ->  там лежит 40
```

Ассемблер не знает типов: `a[i]` — это `a + i * sizeof(T)` **в байтах**,
и `sizeof` подставляете вы, через scale. Масштаб — только 1, 2, 4, 8,
ровно размеры `char`, `short`, `int`, `long`/указателя. Для элементов
другого размера индекс считают отдельно (`imul`, `lea`).

Что будет, если забыть масштаб: `[rdi + rcx]` при `rcx = 3` даст адрес
`0x1003` — середину `a[0]`. Прочитаем 4 байта `0x1003…0x1006`:
старший байт `a[0]` и три младших байта `a[1]` — бессмысленное число.

Индекс может быть отрицательным: `[rdi + rcx*4]` при `rcx = -1` — это
элемент **перед** `rdi`. Так работает `p[-1]`.

### 2.3. Размер операнда

Размер обращения определяется регистром:

```asm
mov al, [rdi]    # 1 байт
mov ax, [rdi]    # 2 байта
mov eax, [rdi]   # 4 байта
mov rax, [rdi]   # 8 байт
```

Если регистра нет — размер обязателен:

```asm
mov dword ptr [rdi], 0         # 4 байта нулей
inc byte ptr [rdi + rcx]       # байтовый счётчик
cmp qword ptr [rdi], -1
```

`byte ptr` (1), `word ptr` (2), `dword ptr` (4), `qword ptr` (8),
`xmmword ptr` (16), `ymmword ptr` (32).

Почему? В `mov [rdi], 0` ассемблеру непонятно, сколько нулей писать:
1, 2, 4 или 8 байт? Регистр подсказал бы размер, а у константы размера
нет. `dword ptr` можно читать как «обращаемся к памяти как к `int`».

Классическая ошибка — неверный размер при правильном адресе:
`add rax, [rdi + rcx*4]` прочтёт **8** байт (по размеру `rax`), то есть
два соседних `int`. Ассемблер не возразит.

Пример с массивом выше: `mov rax, [rdi]` при `rdi = 0x1000` прочитает
байты `0x1000…0x1007` — это `a[0]` и `a[1]` вместе. Благодаря
little-endian: `rax = 0x00000014_0000000A` (20 в старшей половине, 10 в
младшей) = 85899345930. Совсем не 10.

То же при записи: `mov [rdi + rcx*4], rdx` (8 байт) для `int`-массива
перепишет **и** `a[i]`, **и** `a[i+1]`.

### 2.4. Расширение при загрузке

Те же `movzx`/`movsx`, что в главе 01, работают и с памятью. Размер
источника тогда указывается через `ptr`:

| Нужно | Инструкция |
|---|---|
| `char` → `int`/`long` | `movzx eax, byte ptr [rdi]` |
| `ichar` → `long` | `movsx rax, byte ptr [rdi]` |
| `short` → `int` | `movsx eax, word ptr [rdi]` |
| `ushort` → `int` | `movzx eax, word ptr [rdi]` |
| `int` → `long` | `movsxd rax, dword ptr [rdi]` |
| `uint` → `ulong` | `mov eax, [rdi]` |

Типичная ситуация: прочитать байт и использовать его как **индекс**.
`mov al, [rdi]` записывает только 8 бит — в битах 8–63 `rax` остаётся
мусор. Если потом написать `[rdx + rax*4]`, процессор использует весь
`rax`, мусор в том числе → адрес «улетит», будет segfault. Решение —
`movzx eax, byte ptr [rdi]`: весь `rax` = значение байта.

> **Коротко:** адрес = база + индекс×масштаб + смещение. Масштаб —
> `sizeof` элемента (1/2/4/8). Размер обращения задаёт регистр, а без
> регистра — `byte/word/dword/qword ptr`. Маленькие типы читайте через
> `movzx`/`movsx`.

> **Частые ошибки**
> * Забыть масштаб: `[rdi + rsi]` вместо `[rdi + rsi*4]`.
> * Перепутать размер: 64-битный регистр для 32-битного элемента.
> * Использовать байт из `mov al, [..]` как индекс без `movzx`.

## 3. RIP-relative адресация и глобальные данные

### 3.1. Зачем адрес «относительно rip»

Исполняемые файлы в Linux собираются как **PIE** (position-independent
executable): ядро загружает их по случайному адресу (ASLR). Значит,
абсолютных адресов глобальных переменных в коде быть не может. Вместо
этого адресуются относительно текущей инструкции:

**ASLR** (address space layout randomization) — защита: при каждом
запуске программа оказывается по новому адресу, чтобы атакующему было
труднее угадать, где что лежит.

Аналогия: вы не знаете, на какой улице поставят ваш дом, но знаете, что
сарай всегда в 20 шагах от крыльца. «Сарай = крыльцо + 20» работает на
любой улице. Код и данные загружаются **вместе**, поэтому расстояние
между инструкцией и переменной известно заранее, и ассемблер вписывает
его в инструкцию.

### 3.2. Пример

```asm
    .section .rodata
table:  .quad 1, 2, 3, 5, 8      # 5 восьмибайтных чисел
msg:    .asciz "hello"           # строка с нулём на конце

    .data
counter: .quad 0

    .text
    mov rax, [rip + counter]     # прочитать глобальную
    inc qword ptr [rip + counter]
    lea rdi, [rip + msg]         # адрес строки
    lea rcx, [rip + table]
    mov rax, [rcx + rsi*8]       # table[i]: rip нельзя совместить с index
```

Ограничение: в RIP-relative нельзя добавить index. Поэтому сначала
`lea` адреса таблицы в регистр, потом индексирование.

Полный рабочий пример — таблица чисел Фибоначчи и счётчик вызовов:

```asm
    .intel_syntax noprefix
    .section .rodata                # константы: только чтение
    .p2align 3                      # выровнять по 8 байт
fib_table: .quad 1, 1, 2, 3, 5, 8, 13, 21

    .data                           # изменяемые глобальные
    .p2align 3
call_count: .quad 0

    .text
    .globl asm_fib_at
asm_fib_at:                         # long asm_fib_at(long i)
    inc qword ptr [rip + call_count]  # call_count++ (8 байт в памяти)
    lea rcx, [rip + fib_table]      # rcx = &fib_table[0]
    mov rax, [rcx + rdi*8]          # rax = fib_table[i]
    ret

    .globl asm_calls
asm_calls:                          # long asm_calls()
    mov rax, [rip + call_count]     # прочитать глобальную
    ret
    .section .note.GNU-stack,"",@progbits
```

`asm_fib_at(6)` вернёт 13, `asm_fib_at(7)` — 21, после этого
`asm_calls()` — 2. Обратите внимание: `.rodata` и `.data` переключают
секцию, а `.text` возвращает нас в код. Попытка записать в `.rodata`
даст segfault — эта память только для чтения.

### 3.3. Директивы данных

Директивы данных: `.byte`, `.short` (2), `.long` (4), `.quad` (8),
`.ascii` (без нуля), `.asciz`/`.string` (с нулём), `.zero N` (N нулевых
байт), `.p2align k` (выравнивание по 2^k).

Осторожно с именами: `.long` в GNU as — это **4** байта (как `int`), а
не 8, как `long` в C3. 8 байт — `.quad`.

> **Коротко:** глобальные данные объявляют в `.data`/`.rodata` и читают
> как `[rip + имя]`. Для индексации — сначала `lea` адреса в регистр.

> **Частые ошибки**
> * `[rip + table + rcx*8]` — так нельзя.
> * Писать в `.rodata` — segfault.
> * Забыть вернуться в `.text` после данных — код окажется в секции данных.

## 4. `lea`: адрес без обращения к памяти

### 4.1. Идея

`lea dst, [выражение]` вычисляет адрес и кладёт **его**, не читая память:

```asm
mov rax, [rdi + rsi*4]    # rax = a[i]      (чтение памяти)
lea rax, [rdi + rsi*4]    # rax = &a[i]     (просто арифметика)
```

`lea` = **l**oad **e**ffective **a**ddress. Аналогия: `mov` с памятью —
«сходи к ячейке номер N и принеси, что там лежит». `lea` — «просто
скажи мне номер N». Никакого похода на склад — значит, и упасть с
segfault `lea` не может, даже если адрес бессмысленный.

| `rdi = 0x1000`, `rsi = 3` | `rax` после |
|---|---|
| `mov rax, [rdi + rsi*4]` | содержимое памяти по адресу `0x100C` |
| `lea rax, [rdi + rsi*4]` | `0x100C` |

### 4.2. `lea` как калькулятор

Поскольку это просто `base + index*scale + disp`, `lea` — удобный
трёхоперандный калькулятор:

| Выражение | Код |
|---|---|
| `a + b` | `lea rax, [rdi + rsi]` |
| `a + b + 7` | `lea rax, [rdi + rsi + 7]` |
| `x * 3` | `lea rax, [rdi + rdi*2]` |
| `x * 5` | `lea rax, [rdi + rdi*4]` |
| `x * 9 + 1` | `lea rax, [rdi + rdi*8 + 1]` |
| `x * 8 - 4` | `lea rax, [rdi*8 - 4]` |
| `x * 10` | `lea rax, [rdi + rdi*4]` + `add rax, rax` |
| `(int)(a + b)` | `lea eax, [rdi + rsi]` — 32-битный результат |

Как это получается: `x * 5` = `x + x*4` — база `x`, индекс `x`, масштаб 4.
`x * 9` = `x + x*8`. Произвольные множители раскладывают на шаги:
`x * 10` = `(x * 5) * 2`, `x * 15` = `(x * 5) * 3` — две `lea`.

Трассировка `x * 10` при `x = 7`:

| Инструкция | `rax` |
|---|---|
| `lea rax, [rdi + rdi*4]` | 7 + 28 = 35 |
| `lea rax, [rax + rax]` (или `add rax, rax`) | 70 |

Плюсы: не портит источники, **не меняет флаги**, одна инструкция вместо
`mov` + `add` + `shl`. Минусы: только сложение и масштаб 1/2/4/8; на
некоторых CPU «сложная» `lea` с тремя компонентами медленнее (3 такта
вместо 1 на старых Intel) — компиляторы это учитывают.

> **Коротко:** `lea` считает адресное выражение и кладёт результат, ничего
> не читая. Это `&a[i]`, а заодно быстрый `a + b*k + c` без порчи
> флагов и источников.

> **Частые ошибки**
> * `mov` вместо `lea`, когда нужен адрес (или наоборот).
> * Пытаться написать `lea rax, [rdi*3]` — масштаба 3 нет; нужно `[rdi + rdi*2]`.

## 5. Обход массива

Два стиля, оба встречаются в коде компиляторов.

### 5.1. Индекс

```asm
# long sum(int* a, usz n)
    xor eax, eax                          # sum = 0
    xor ecx, ecx                          # i = 0
    test rsi, rsi                         # n == 0?
    jz .Ldone                             # пустой массив -> 0
.Lloop:
    movsxd rdx, dword ptr [rdi + rcx*4]   # rdx = (long)a[i]
    add rax, rdx                          # sum += a[i]
    inc rcx                               # i++
    cmp rcx, rsi                          # i < n ?
    jb .Lloop                             # беззнаково: размеры не бывают < 0
.Ldone:
    ret
```

Трассировка для `a = {7, -2, 5}` по адресу `0x1000`, `n = 3`:

| После итерации | `rcx` (до `inc`) | адрес | `rdx` | `rax` |
|---|---|---|---|---|
| 1 | 0 | `0x1000` | 7 | 7 |
| 2 | 1 | `0x1004` | −2 | 5 |
| 3 | 2 | `0x1008` | 5 | 10 |

После третьей итерации `rcx = 3`, `cmp 3, 3` → `jb` не прыгает →
`ret` с `rax = 10`. Обратите внимание на `movsxd`: −2 как 32-битное
число `0xFFFFFFFE` превратилось в 64-битное −2, и сумма осталась
правильной.

### 5.2. Бегущий указатель

```asm
    lea rsi, [rdi + rsi*4]   # end = a + n
    xor eax, eax
    cmp rdi, rsi
    jae .Ldone
.Lloop:
    movsxd rdx, dword ptr [rdi]
    add rax, rdx
    add rdi, 4
    cmp rdi, rsi
    jb .Lloop
.Ldone:
```

Здесь `rdi` сам «шагает» по массиву на 4 байта за раз, а `rsi` указывает
на байт **сразу после** последнего элемента («конец», как `end()` в C++).
Цикл идёт, пока указатель меньше конца.

```
 rdi ->  [ 7 ][ -2 ][ 5 ]   <- rsi (end) указывает сюда, за массив
```

Указатели сравниваются **беззнаково** (`jb`, `jae`): адреса — не числа
со знаком.

### 5.3. Отрицательный индекс

Ещё один приём, который любят компиляторы: отрицательный индекс,
бегущий к нулю. `rdi` указывает на *конец* массива, `rcx` — от `-n` до 0:
`[rdi + rcx*4]`, `inc rcx`, `jnz` — без `cmp`.

### 5.4. Два указателя навстречу

Для задач вроде «развернуть массив» удобны два указателя: один с начала,
другой с конца, они движутся навстречу, пока не встретятся.

```
шаг 0:  lo -> [1][2][3][4][5] <- hi
шаг 1:      [5] lo->[2][3][4]<-hi [1]      (обменяли и сдвинули)
шаг 2:      [5][4] lo,hi->[3] [2][1]       (lo == hi — стоп)
```

Последний элемент массива — это `a + (n - 1) * sizeof(T)`; через `lea`:
`[rdi + rsi*4 - 4]`. Будьте осторожны с `n = 0`: такой адрес окажется
**перед** массивом.

> **Коротко:** обходите массив индексом (`[base + i*size]`) или
> указателем (`add ptr, size`). Проверяйте `n = 0` до цикла. Указатели
> и размеры сравнивайте беззнаково.

> **Частые ошибки**
> * Шаг указателя 1 вместо `sizeof` элемента.
> * Сравнение указателей через `jl`/`jg`.
> * Нет проверки на пустой массив.

## 6. Массивы структур и шаг, не равный 1/2/4/8

Для `struct Vec3 { float x, y, z; }` (12 байт) `v[i].y` находится по
адресу `v + i*12 + 4`. Масштаба 12 нет, но `12 = 3 * 4`:

```asm
    lea rax, [rsi + rsi*2]               # rax = i * 3
    movss xmm0, [rdi + rax*4 + 4]        # v[i].y
```

Это буквально то, что сгенерировал c3c `-O2` для
`fn float gety(Vec3* v, long i) => v[i].y;` (с AVX — `vmovss`).

Разбор: `rax*4` = `i*3*4` = `i*12` — начало `v[i]`; `+ 4` — смещение поля
`y` внутри структуры (после 4-байтового `x`). `movss` — загрузка одного
`float` в регистр `xmm0` (глава 09).

## 7. Как это делает компилятор

`fn int get(int* a, long i) => a[i];`

`-O2`:

```asm
get:
    mov eax, dword ptr [rdi + rsi*4]   # eax = a[i]
    ret
```

`-O0` (каждая переменная — в памяти стека, плюс проверки безопасного
режима):

```asm
get:
    push rbp
    mov rbp, rsp
    sub rsp, 0x80
    mov [rbp - 0x8], rdi          # a  -> в стек
    mov [rbp - 0x10], rsi         # i  -> в стек
    mov rax, [rbp - 0x8]
    mov rcx, [rbp - 0x10]
    shl rcx, 2                    # i * 4
    add rax, rcx                  # &a[i]
    mov [rbp - 0x60], rax
    and rax, 3                    # адрес выровнен по 4?
    ...                           # если нет — переход к panic
    mov rax, [rbp - 0x60]
    mov eax, [rax]                # само чтение a[i]
    add rsp, 0x80
    pop rbp
    ret
```

Одна инструкция полезной работы на два десятка служебных. Каждая
переменная живёт в стеке (так её видит отладчик), а перед
разыменованием c3c в безопасном режиме (`-O0`, `-O1`) проверяет
выравнивание указателя и вызывает panic при нарушении. Увидев в
дизассемблере «лишние» ветки с вызовом в конце функции — это они.

## 8. Выравнивание

**Выравнивание** (alignment) — требование, чтобы адрес данных был
кратен некоторому числу. Данные размера N принято класть по адресу,
кратному N («естественное выравнивание»). x86 разрешает невыровненные
обращения к целым (они чуть медленнее, если пересекают границу
кеш-линии в 64 байта), но:

* SSE-инструкции вида `movaps`/`movdqa` **требуют** выравнивания по 16
  и падают с SIGSEGV иначе (это всплывёт в главе 05);
* атомарные операции через границу кеш-линии — очень медленные;
* компиляторы C3/C рассчитывают на выравнивание и могут проверять его.

Как проверить: адрес выровнен по 2^k, если его младшие k бит — нули.
`0x1008` выровнен по 8 (`…1000` в двоичном), `0x100C` — только по 4
(`…1100`). Отсюда `and rax, 3` в коде `-O0` выше: результат 0 → адрес
кратен 4.

**Кеш-линия** — порция в 64 байта, которой память ходит между RAM и
кешем. Если `long` начинается по адресу `0x103C`, его байты лежат в двух
линиях (`0x1000–0x103F` и `0x1040–0x107F`) — процессору придётся
работать с обеими.

Глобальные данные выравнивайте директивой `.p2align 3` (по 8) или
`.p2align 4` (по 16).

> **Коротко:** клади N-байтовые данные по адресам, кратным N. Для целых
> это вопрос скорости, для части SSE-инструкций — вопрос падения.

## 9. Подводные камни

> **Частые ошибки**
>
> * **Масштаб не тот.** `[rdi + rsi]` вместо `[rdi + rsi*4]` для `int*`.
> * **Размер не тот.** `mov [rdi], rdx` пишет 8 байт и затирает соседа.
> * **Байт как индекс без `movzx`.** `mov al, [rdi]` и затем `[rdx + rax*4]`
>   — в старших битах `rax` мусор → segfault.
> * **`mov` вместо `lea`.** Хотели адрес — получили значение (и, скорее
>   всего, segfault позже).
> * **Знаковое сравнение указателей** (`jl` вместо `jb`).
> * **RIP + index.** `[rip + table + rcx*8]` не существует.
> * **Указатель на локальную переменную после `ret`.** Память стека уже
>   чужая (глава 06).
> * **`inc byte ptr` для 4-байтового счётчика** — дойдёт до 255 и
>   «перевернётся» в 0, не тронув остальные байты.

## Как это связано с упражнениями

* **`a0401` index** — `a[i]` для `int*`, запись `a[i] = v`, `a[i]` для
  `long*`. Разделы 2.1–2.3. В каждой функции проверьте две вещи:
  масштаб = `sizeof` элемента, ширина регистра = размер элемента. Тест с
  отрицательным индексом проверяет, что индекс используется целиком
  (он `long`).
* **`a0402` sum** — найти ошибку в сумме и написать максимум массива.
  Разделы 2.3 (почему `add rax, [..]` читает два элемента), 2.4
  (`movsxd` из памяти), 5.1 (трассировка). Для максимума вспомните
  главу 03: элементы знаковые — какой переход? Массив может быть целиком
  из отрицательных чисел.
* **`a0403` lea** — вернуть адрес `&base[i + 2]` и умножения через `lea`.
  Раздел 4 целиком. Для адреса подумайте, какое смещение у «+2
  элемента» `int`. Для `10x` — таблица 4.2 и трассировка.
* **`a0404` histogram** — `counts[data[i]]++`. Разделы 2.3 и 2.4 и
  «Частые ошибки» в 9. Обе ошибки в шапке — про размеры: индекс-байт
  нужно расширить, счётчик — `uint` (какой `ptr`?). Функция не обнуляет
  счётчики, только прибавляет.
* **`a0405` reverse** — разворот на месте и линейный поиск. Разделы 5.2 и
  5.4. Для разворота: адрес последнего элемента, беззнаковое сравнение
  указателей, `n = 0` и `n = 1`. Обмен — через два регистра (раздел 1.2).
  Для поиска: элементы `long` (масштаб 8), вернуть −1, если не найдено,
  в том числе при `n = 0`.

## Словарик

| Термин | Простыми словами |
|---|---|
| **`[адрес]`** | обращение к памяти по адресу, аналог `*p` |
| **load / store** | чтение из памяти в регистр / запись из регистра в память |
| **эффективный адрес** | итоговый адрес, вычисленный из base + index×scale + disp |
| **base / index / scale / displacement** | начало / номер элемента / размер элемента / постоянная добавка |
| **`byte/word/dword/qword ptr`** | явный размер обращения: 1/2/4/8 байт |
| **CISC** | архитектура, где арифметика может работать прямо с памятью |
| **RIP-relative** | адрес, отсчитанный от текущей инструкции: `[rip + имя]` |
| **PIE / ASLR** | программа грузится по случайному адресу, поэтому адреса — относительные |
| **`.data` / `.rodata` / `.bss`** | секции изменяемых данных / констант / нулевых данных |
| **`.byte/.short/.long/.quad`** | данные по 1/2/4/8 байт (`.long` — это 4!) |
| **`lea`** | вычислить адрес без чтения памяти; заодно калькулятор |
| **бегущий указатель** | обход массива, где указатель сам увеличивается на размер элемента |
| **конец массива (end)** | адрес сразу за последним элементом |
| **выравнивание** | адрес кратен размеру данных (или 16, 64…) |
| **кеш-линия** | блок в 64 байта, которым память обменивается с кешем |
| **read-modify-write** | инструкция, которая читает память, меняет и пишет обратно (`inc [..]`) |
