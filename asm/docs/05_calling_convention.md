# Глава 05. Соглашение о вызовах System V

## Карта главы

**Что вы узнаете.**

* Как `call` и `ret` работают со стеком — по шагам, с картинками.
* Полные правила передачи аргументов: регистры, стек (7-й и дальше),
  `float`/`double`, структуры, возврат значений.
* Что такое **caller-saved** и **callee-saved** регистры и как не сломать
  вызывающий код.
* Правило **выравнивания стека** по 16 байт перед `call` и как считать его
  в уме.
* Что такое **красная зона**.
* Как вызывать из ассемблера функции C3 и libc (`strlen`, `snprintf`,
  `qsort`) и как отдавать свои функции как колбэки.

**Зачем это нужно.** Всё, что мы делали до сих пор, держалось на
договорённостях: аргумент в `rdi`, результат в `rax`. Эти договорённости
записаны в документе **System V AMD64 ABI** — его соблюдают Linux, macOS,
FreeBSD и все компиляторы под них (C, C++, Rust, Zig, C3). Благодаря ему
функция, написанная на ассемблере, может вызвать `printf`, а C3 —
вызвать вашу функцию. В этой главе — полный разбор ABI для
целочисленного кода и главное, чего начинающие обычно не знают:
callee-saved регистры и выравнивание стека.

**Что нужно знать заранее.** Главы 01–04: регистры, `mov`, `lea`, циклы,
обращения к памяти `[rsp + 8]`, RIP-relative адресация (`lea rdi, [rip +
fmt]`). Из главы 00 — что стек растёт вниз и `rsp` указывает на вершину.

**Упражнения:** `a0501`–`a0506`.

| Упражнение | Разделы |
|---|---|
| `a0501` stack_args | 1, 2.3 |
| `a0502` callee_saved | 3 |
| `a0503` call_c3 | 3, 4, 6, 9 |
| `a0504` libc | 4, 7 |
| `a0505` apply | 3, 4, 8, 9 |
| `a0506` qsort | 4, 7, 8 |

## 1. `call` и `ret`

### 1.1. Стек и `push`/`pop`

**Стек** — область памяти, которую используют как стопку: кладём сверху,
снимаем сверху. «Верх» — это адрес в `rsp`. У x86 стек растёт **вниз**:
чтобы положить, `rsp` уменьшают.

Стек растёт вниз: `push x` = `sub rsp, 8; mov [rsp], x`; `pop x` =
`mov x, [rsp]; add rsp, 8`.

Трассировка (`rsp` в начале `0x7000`, `rax = 5`, `rbx = 9`):

| Инструкция | `rsp` после | что лежит в памяти |
|---|---|---|
| (начало) | `0x7000` | |
| `push rax` | `0x6FF8` | `[0x6FF8] = 5` |
| `push rbx` | `0x6FF0` | `[0x6FF0] = 9`, `[0x6FF8] = 5` |
| `pop rcx` | `0x6FF8` | `rcx = 9` |
| `pop rdx` | `0x7000` | `rdx = 5` |

```
после двух push:              после двух pop:
  0x7000 | ...  |               0x7000 | ...  | <- rsp
  0x6FF8 |  5   |               0x6FF8 |  5   |  (данные остались, но
  0x6FF0 |  9   | <- rsp        0x6FF0 |  9   |   это уже «свободно»)
```

Снимается в обратном порядке: последним положили — первым сняли. Отсюда
правило «`pop` в обратном порядке».

### 1.2. `call` и `ret`

```asm
call f      # push адрес_следующей_инструкции; jmp f
ret         # pop rip
```

Значит, в момент входа в функцию `[rsp]` — адрес возврата. Если к
моменту `ret` вы не вернули `rsp` ровно туда, `ret` прыгнет по мусору —
SIGSEGV (в лучшем случае).

Пример (адреса условные). Вызывающий код:

```asm
0x401000:  call asm_f        # 5 байт
0x401005:  mov rbx, rax      # сюда нужно вернуться
```

| Момент | `rsp` | `[rsp]` | `rip` |
|---|---|---|---|
| перед `call` | `0x7000` | ? | `0x401000` |
| после `call` (вход в `asm_f`) | `0x6FF8` | `0x401005` | `asm_f` |
| перед `ret` (если `rsp` вернули) | `0x6FF8` | `0x401005` | ... |
| после `ret` | `0x7000` | ? | `0x401005` |

`ret` ничего не знает о функциях — он просто берёт 8 байт с вершины
стека и прыгает туда. Если вы сделали `push` и забыли `pop`, на вершине
окажется ваше значение, и `ret` прыгнет «по нему».

> **Коротко:** `push` = `rsp -= 8` + запись, `pop` = чтение + `rsp += 8`.
> `call` кладёт адрес возврата на стек, `ret` его снимает. К `ret` `rsp`
> должен быть ровно таким, каким был на входе.

## 2. Передача аргументов

### 2.1. Целые и указатели

| № | Регистр |
|---|---|
| 1 | `rdi` |
| 2 | `rsi` |
| 3 | `rdx` |
| 4 | `rcx` |
| 5 | `r8` |
| 6 | `r9` |
| 7+ | стек |

### 2.2. Плавающая точка

`float` и `double` — в `xmm0`–`xmm7`, **независимо** от целых. Функция
`f(int a, double x, long b)` получит `a` в `edi`, `x` в `xmm0`, `b` в
`rsi`. Подробно — глава 09.

«Независимо» значит: у целых и у дробных — два отдельных счётчика. `x`
не «занимает» `rsi`; следующий целый аргумент всё равно идёт в `rsi`.

### 2.3. Аргументы на стеке

Седьмой и следующие целые аргументы вызывающий кладёт в стек, по 8 байт
на каждый (даже на `char`), причём 7-й — по меньшему адресу. В момент
входа:

```
[rsp + 24]  9-й аргумент
[rsp + 16]  8-й аргумент
[rsp + 8]   7-й аргумент
[rsp]       адрес возврата
```

Откуда такое расположение: вызывающий сначала кладёт стековые аргументы
(последний — первым, так что 7-й оказывается ближе всех к вершине), а
потом `call` кладёт поверх адрес возврата. Поэтому сразу за адресом
возврата (8 байт) — 7-й аргумент.

Пример: `long seventh(long a, …, long g)` возвращает 7-й аргумент:

```asm
asm_seventh:
    mov rax, [rsp + 8]       # [rsp] — адрес возврата, [rsp + 8] — 7-й аргумент
    ret
```

Если аргумент `int`, в его 8-байтовой ячейке значимы только младшие 4
байта, а старшие — мусор (как с регистрами в главе 01). Читайте его как
`dword`: `mov eax, [rsp + 8]` или `movsxd rax, dword ptr [rsp + 8]`.

Важно: смещения `[rsp + 8]` верны **только пока вы не двигали `rsp`**.
После одного `push` всё сдвигается на 8:

```
сразу при входе:              после push rbx:
  [rsp+16] 8-й аргумент         [rsp+24] 8-й аргумент
  [rsp+8]  7-й аргумент         [rsp+16] 7-й аргумент
  [rsp]    адрес возврата       [rsp+8]  адрес возврата
                                [rsp]    сохранённый rbx
```

После пролога с `push rbp; mov rbp, rsp` те же аргументы — `[rbp + 16]`,
`[rbp + 24]`, … Стековые аргументы убирает **вызывающий** (после `call`
он делает `add rsp, N`).

### 2.4. Структуры

* Структуры до 16 байт раскладываются по регистрам «по восьмибайтовым
  кускам»: целочисленный кусок — в следующий свободный целый регистр,
  кусок из float/double — в xmm. `struct { long a; long b; }` займёт два
  целых регистра.
* Структуры больше 16 байт (или с невыровненными полями) передаются в
  памяти — копией на стеке.
* `uint128`/`int128` — пара регистров, младшая половина первой.

### 2.5. Возврат значения

| Тип | Где |
|---|---|
| целое/указатель до 64 бит | `rax` (часть: `eax`, `ax`, `al`) |
| 128-битное целое, структура из двух целых | `rdx:rax` |
| `float`/`double` | `xmm0` |
| структура до 16 байт из double | `xmm0`, `xmm1` |
| большая структура | вызывающий передаёт скрытый указатель в `rdi`, функция пишет туда и возвращает его же в `rax` |

Важный нюанс: при возврате `int` старшие 32 бита `rax` не определены,
при возврате `bool` значимы только младшие 8 бит. Вызывающий не должен
на них полагаться.

> **Коротко:** 6 целых аргументов в регистрах, остальные — на стеке по 8
> байт, 7-й по `[rsp + 8]` на входе. Дробные — в `xmm0..7` по своему
> счётчику. Результат — `rax` (или `rdx:rax`, или `xmm0`).

> **Частые ошибки**
> * Читать 7-й аргумент по `[rsp]` — там адрес возврата.
> * Читать `int`-аргумент со стека 8 байтами — в старших 4 мусор.
> * Двигать `rsp` и не пересчитать смещения.

## 3. Регистры: кто кого сохраняет

### 3.1. Идея

Представьте общую кухню, на которой готовят по очереди. Договорились:
**часть полок «общие»** — любой может их освободить и занять, поэтому
если вам дорога вещь на общей полке, уберите её к себе, прежде чем
пустить кого-то готовить. **Часть полок «личные»** — тот, кто готовит,
может временно ими пользоваться, но обязан вернуть всё, как было.

* «Общие полки» — **caller-saved** регистры (сохраняет **вызывающий**,
  caller, если ему надо): вызванная функция портит их без спроса.
* «Личные полки» — **callee-saved** регистры (сохраняет **вызываемый**,
  callee): вызванная функция обязана вернуть их неизменными.

| Регистры | Категория | Правило |
|---|---|---|
| `rax`, `rcx`, `rdx`, `rsi`, `rdi`, `r8`–`r11` | caller-saved (volatile, scratch) | функция портит свободно; кто вызывает — сохраняет сам, если нужно |
| `rbx`, `rbp`, `r12`–`r15` | callee-saved (non-volatile) | функция обязана вернуть их как было |
| `rsp` | особый | должен вернуться на место |
| `xmm0`–`xmm15` | все caller-saved | (в Windows x64 — иначе!) |
| флаг DF | | 0 на входе и на выходе |

Синонимы, которые вы встретите: **volatile** («изменчивый») = caller-saved,
**non-volatile** = callee-saved, **scratch** («черновик») = caller-saved.

Почему не сделать все регистры одного вида? Если бы все были
callee-saved — каждая крошечная функция тратила бы время на сохранение
всего, чем пользуется. Если бы все были caller-saved — вызывающий
сохранял бы всё живое перед каждым `call`. Смесь даёт выбор: короткоживущие
значения — в volatile (бесплатно), долгоживущие — в callee-saved
(сохраняем один раз в начале функции).

### 3.2. Как этим пользоваться

* **Листовая функция** (никого не вызывает) обычно обходится volatile-
  регистрами: их 9, плюс аргументы уже в них.
* **Функция с вызовами**: всё, что должно пережить `call`, держите в
  callee-saved. Сохраните их в начале (`push`), восстановите в конце
  (`pop` в обратном порядке).

```asm
f:
    push rbx                # сохранить «личную полку» вызывающего
    push r12
    ...                 # rbx, r12 — наши, переживают любые call
    pop r12                 # вернуть в обратном порядке
    pop rbx
    ret
```

Что будет, если перепутать порядок `pop`:

| | `push rbx` (rbx = A), `push r12` (r12 = B) | `pop rbx`, `pop r12` (неверно) |
|---|---|---|
| стек | `[rsp] = B`, `[rsp+8] = A` | |
| после | | `rbx = B`, `r12 = A` — поменялись местами! |

### 3.3. Почему это так коварно

Нарушение — один из самых коварных багов: ваша функция работает
правильно, а ломается **вызывающий** код, иногда через миллион
инструкций. В упражнениях этой главы стенд `abi_check.s` кладёт в
callee-saved регистры «канарейки» и проверяет их после вызова.

**Канарейка** — заранее известное значение (у стенда `0x1111…`,
`0x2222…`), которое кладут куда-то, чтобы потом проверить: не изменилось
ли. Название — от шахтёрских канареек, которые первыми «замечали» газ.

Стенд `abi_call(fn, a, b, c, d)` работает так:

1. сохраняет свои callee-saved и кладёт в `rbx`, `rbp`, `r12`–`r15`
   канарейки;
2. вызывает вашу функцию;
3. сравнивает регистры с канарейками и `rsp` с запомненным; при
   расхождении ставит биты в `abi_errors()`: 1 — испорчен callee-saved,
   2 — `rsp` не вернулся, 4 — невыровненный стек при вызове колбэка.

> **Коротко:** `rax, rcx, rdx, rsi, rdi, r8–r11` — можно портить, но и
> после любого `call` они испорчены. `rbx, rbp, r12–r15` — переживают
> вызовы, но если трогаете — `push` в начале, `pop` в обратном порядке
> в конце.

> **Частые ошибки**
> * Использовать `rbx`/`r12` без сохранения.
> * Хранить счётчик цикла в `rcx` через `call`.
> * `pop` в том же порядке, что `push`.

## 4. Выравнивание стека

### 4.1. Правило

Правило: **перед каждой инструкцией `call` `rsp` кратен 16.** Значит,
сразу после входа в функцию (call положил 8 байт) `rsp ≡ 8 (mod 16)`.

(`≡ 8 (mod 16)` читается «даёт остаток 8 при делении на 16». В hex
это значит: последняя цифра адреса — `8`. Кратен 16 — последняя цифра `0`.)

Почему на входе остаток 8: вызывающий выровнял `rsp` до `…0`, потом
`call` положил 8 байт адреса возврата → `…8`. Каждый `push` или
`sub rsp, 8` сдвигает ещё на 8, переключая `…0` ↔ `…8`.

### 4.2. Подсчёт

Подсчёт для функции, которая что-то вызывает:

| Пролог | rsp mod 16 после пролога | Выровнен? |
|---|---|---|
| ничего | 8 | нет → `sub rsp, 8` |
| 1 push | 0 | да |
| 2 push | 8 | нет → `sub rsp, 8` |
| 3 push | 0 | да |
| `push rbp` + `sub rsp, 32` | 0 | да |
| `sub rsp, 40` | 0 | да |

Формула: `8 + 8·(число push) + (размер sub)` должно делиться на 16.

Трассировка (на входе `rsp = 0x7FF8`):

| Инструкция | `rsp` | последняя hex-цифра | можно `call`? |
|---|---|---|---|
| (вход) | `0x7FF8` | 8 | нет |
| `push rbx` | `0x7FF0` | 0 | да |
| `push r12` | `0x7FE8` | 8 | нет |
| `sub rsp, 8` | `0x7FE0` | 0 | **да** |

### 4.3. Зачем это нужно

Зачем это нужно? SSE-инструкции `movaps`/`movdqa` требуют адрес, кратный
16, и компиляторы, зная, что стек выровнен, используют их для локальных
переменных. glibc в `printf` сохраняет xmm-регистры именно `movaps`.
Поэтому невыровненный стек — это **«работает, пока не перестанет»**:
простые функции проходят, а `snprintf` с `double` падает с SIGSEGV
глубоко внутри libc. Упражнение `a0504` показывает это вживую.

Стенд `harness_trash()`, которую вызывают колбэки в упражнениях,
проверяет `rsp & 15 == 8` на входе — то есть, что стек был выровнен
перед `call`.

> **Коротко:** перед `call` последняя hex-цифра `rsp` — 0. На входе она
> 8; каждый `push` переключает 8↔0. Чётное число `push` → добавьте
> `sub rsp, 8` (и `add rsp, 8` перед `pop`).

> **Частые ошибки**
> * Забыли `sub rsp, 8` при чётном числе `push`.
> * Добавили `sub rsp, 8`, но забыли `add rsp, 8` перед `pop` — `pop`
>   достанут не то, `ret` уйдёт в мусор.
> * Выровняли в начале, но сделали `push` внутри цикла перед `call`.

## 5. Красная зона

Листовая функция может использовать 128 байт **ниже** `rsp` без `sub
rsp`: ABI гарантирует, что обработчики сигналов их не затрут. Это
экономит две инструкции:

```asm
leaf:
    mov [rsp - 8], rdi       # временная переменная в красной зоне
    ...
    ret
```

```
         | адрес возврата | <- rsp
         |  красная зона  |  [rsp-8] ... [rsp-128]: можно писать
         |   (128 байт)   |  без sub rsp — но только в листовой функции
         |                |
```

Но любая `call` запишет адрес возврата прямо туда. Поэтому красная зона
— только для функций без вызовов. (В ядре Linux её отключают флагом
`-mno-red-zone`: прерывания там пишут на тот же стек.)

**Обработчик сигнала** — функция, которую ОС может вызвать посреди вашей
программы (например, по Ctrl+C). Она использует ваш стек, но ABI
обещает, что она начнёт ниже красной зоны.

## 6. Вызов функций C3 из ассемблера

Функция C3 по умолчанию имеет «декорированное» имя (`main.c3_weight`
или `module__name`), которое в GNU as неудобно писать. Решение —
`@export` с явным именем:

```c3
fn long c3_weight(int x) @export("c3_weight") { return (long)x * x + 1; }
```

и в ассемблере:

```asm
    mov edi, [rbx + r14*4]
    call c3_weight
    add r13, rax
```

Без `@export` неиспользуемая функция C3 ещё и выкидывается компилятором,
и линковщик выдаст `undefined reference`.

### 6.1. Полный пример с трассировкой стека

`long asm_sq_sum(long a, long b)` = `c3_sq(a) + c3_sq(b)`, где
`fn long c3_sq(long x) @export("c3_sq") => x * x;`. Значения, которым
нужно пережить `call`: `b` (понадобится для второго вызова) и результат
первого вызова. Значит, два callee-saved регистра.

```asm
    .globl asm_sq_sum
asm_sq_sum:                 # long asm_sq_sum(long a, long b)
    push rbx                # сохранить rbx вызывающего; rsp ≡ 0 (mod 16)
    push r12                # сохранить r12;              rsp ≡ 8 (mod 16)
    sub rsp, 8              # доравнять:                   rsp ≡ 0 (mod 16)
    mov rbx, rsi            # b переживёт call: кладём в callee-saved rbx
    call c3_sq              # rax = c3_sq(a)   (a уже в rdi)
    mov r12, rax            # спрятать результат в callee-saved r12
    mov rdi, rbx            # 1-й аргумент = b
    call c3_sq              # rax = c3_sq(b)
    add rax, r12            # rax = c3_sq(b) + c3_sq(a)
    add rsp, 8              # убрать выравнивание
    pop r12                 # восстановить в обратном порядке
    pop rbx
    ret
```

Стек после пролога (на входе `rsp = 0x7FF8`):

```
  0x7FF8 | адрес возврата    |  <- rsp на входе
  0x7FF0 | старый rbx        |
  0x7FE8 | старый r12        |
  0x7FE0 | (пусто, для выр.) |  <- rsp перед call: ...0 — выровнен
  0x7FD8 | адр. возврата в asm_sq_sum |  <- появится во время call c3_sq
```

Регистры для `asm_sq_sum(3, 4)`:

| После | `rdi` | `rbx` | `r12` | `rax` |
|---|---|---|---|---|
| `mov rbx, rsi` | 3 | 4 | ? | ? |
| `call c3_sq` | мусор | 4 | ? | 9 |
| `mov r12, rax` | мусор | 4 | 9 | 9 |
| `mov rdi, rbx` | 4 | 4 | 9 | 9 |
| `call c3_sq` | мусор | 4 | 9 | 16 |
| `add rax, r12` | мусор | 4 | 9 | 25 |

После `call` в `rdi` «мусор» — функция имела право его испортить. А `rbx`
и `r12` гарантированно уцелели. Этот пример собран и проверен:
`asm_sq_sum(3, 4) = 25`.

> **Коротко:** функцию C3 помечают `@export("имя")` и вызывают `call имя`.
> Всё, что нужно после `call`, — в callee-saved регистрах.

## 7. Вызов libc

Программа на C3 уже слинкована с libc, так что из ассемблера доступны
`strlen`, `memcpy`, `qsort`, `snprintf`, `malloc`… Правила те же, плюс:

**Вариадические функции** (`printf`, `snprintf`) ожидают в `al` верхнюю
границу числа аргументов, переданных в векторных регистрах:

```asm
    .section .rodata
fmt: .asciz "n=%ld x=%.2f"
    .text
asm_format:                  # (buf, size, n, x)
    sub rsp, 8               # выровнять стек
    mov rcx, rdx             # n — 4-й аргумент snprintf
    lea rdx, [rip + fmt]     # формат — 3-й
    mov eax, 1               # один аргумент в xmm (x уже в xmm0)
    call snprintf@PLT
    add rsp, 8
    ret
```

**Вариадическая** функция — функция с переменным числом аргументов
(`...`). Она не знает заранее, сколько и каких аргументов получит, поэтому
ABI просит подсказку: в `al` — сколько `xmm`-регистров используется. Нет
дробных аргументов — `xor eax, eax`.

Разбор: на входе в `asm_format` аргументы лежат в `rdi` (buf), `rsi`
(size), `rdx` (n), `xmm0` (x). `snprintf(buf, size, fmt, n, x)` ждёт
`rdi`, `rsi`, `rdx` = fmt, `rcx` = n, `xmm0` = x. Значит: `rdi`, `rsi` и
`xmm0` уже на месте; `n` переносим из `rdx` в `rcx` (**до** того, как
затрём `rdx` форматом!); результат `snprintf` уже в `eax` — его и вернём.

`@PLT` означает «через таблицу связывания процедур»: адрес функции из
разделяемой libc станет известен только при загрузке. Современный
линковщик сам подставит PLT и для голого `call snprintf`, но `@PLT` —
явная и правильная форма для внешних функций в PIE.

**PLT** (procedure linkage table) — маленькая таблица «трамплинов» в
вашей программе: `call` прыгает в трамплин, а тот — в настоящую функцию
libc, адрес которой загрузчик вписал при старте.

> **Частые ошибки**
> * Забыть `al` перед `printf`/`snprintf`.
> * Затереть аргумент, перекладывая другие (порядок перестановок!).
> * Держать значение в `rsi`/`rdi` через `call strlen` — испорчено.

## 8. Указатели на функции и колбэки

Указатель на функцию — обычное 64-битное число. Вызов по нему —
косвенный `call`:

```asm
    call r13                 # адрес в регистре
    call [rbx + 16]          # адрес в памяти (vtable, таблица методов)
```

Адрес своей функции, чтобы отдать его в C (например, компаратор для
`qsort`):

```asm
    lea rcx, [rip + asm_cmp_desc]
    call qsort@PLT
```

Когда libc вызывает ваш компаратор, *вы* становитесь вызываемым — и
обязаны соблюдать все правила callee: сохранить callee-saved, вернуть
результат правильной ширины (`int` — в `eax`).

**Колбэк** (callback, «обратный вызов») — функция, которую вы передаёте
другой функции, чтобы та её вызвала. `qsort` не знает, как сравнивать
ваши элементы, — она зовёт ваш компаратор.

Указатель на функцию легко держать в callee-saved регистре — тогда он
переживёт сам вызов:

```asm
    mov r13, rdx             # r13 = f (3-й аргумент), сохранён через вызовы
    ...
    mov edi, ...             # аргумент для f
    call r13                 # f(...)
```

Про компараторы: «вернуть `*a - *b`» — популярная, но опасная идиома.
Разность двух `long` может переполниться, а при возврате `int` старшие
32 бита просто отбрасываются: для `2^40 - 0` младшие 32 бита — ноль, и
«больше» превращается в «равно». Надёжно — честно сравнить (`cmp` +
переходы или `setcc`) и вернуть −1/0/1.

## 9. Шаблон функции, которая вызывает другие

```asm
    .globl f
f:
    push rbx                 # сохранить callee-saved, которые используем
    push r12
    push r13
    push r14
    sub rsp, 8               # 4 push — чётное число: доравнять
    mov rbx, rdi             # долгоживущие значения — в callee-saved
    mov r12, rsi
    ...
    call g                   # rdi..r11 после этого — мусор
    ...
    add rsp, 8
    pop r14                  # в обратном порядке
    pop r13
    pop r12
    pop rbx
    ret
```

Порядок работы над такой функцией:

1. Выпишите, какие значения должны пережить `call` (указатель, счётчик,
   сумма, адрес колбэка…). Каждому — callee-saved регистр.
2. Посчитайте `push`. Чётно → `sub rsp, 8`.
3. Напишите эпилог зеркально прологу **сразу**, до тела.
4. Каждый выход из функции (если их несколько) должен идти через эпилог.

## 10. Как это делает компилятор

```c3
extern fn long g(long);
fn long twice_g(long x) @export("twice_g") => g(x) + g(x + 1);
```

`-O2` (clang/LLVM, и c3c тоже):

```asm
twice_g:
    push r14
    push rbx
    push rax                 # «push rax» вместо «sub rsp, 8» — короче на 3 байта
    mov rbx, rdi             # x -> rbx (переживёт call)
    call g
    mov r14, rax             # g(x) -> r14 (переживёт второй call)
    inc rbx                  # x + 1
    mov rdi, rbx
    call g
    add rax, r14             # g(x+1) + g(x)
    add rsp, 8
    pop rbx
    pop r14
    ret
```

Обратите внимание на `push rax` — популярный трюк для выравнивания:
значение не важно, важен сдвиг `rsp` на 8.

**Хвостовой вызов**: если функция заканчивается `return g(...)`,
компилятор с `-O2` заменит `call g; ret` на `jmp g` (восстановив регистры
до перехода). Подробнее — глава 06.

## 11. Отличия других ABI (для общего развития)

* **Windows x64**: аргументы в `rcx`, `rdx`, `r8`, `r9`; вызывающий
  резервирует 32 байта «shadow space»; `rsi`, `rdi`, `xmm6`–`xmm15` —
  callee-saved; красной зоны нет.
* **32-битный x86 (cdecl)**: все аргументы на стеке.
* **AArch64**: аргументы в `x0`–`x7`, адрес возврата в регистре `x30`.

Код из этого трека работает только на Linux/macOS x86-64.

## 12. Подводные камни

> **Частые ошибки**
>
> * **Испортили callee-saved** — ломается вызывающий, а не вы.
> * **Забыли выровнять стек** — падение внутри libc на `movaps`.
> * **pop в неправильном порядке** — регистры поменялись значениями.
> * **Держали значение в volatile-регистре через call** — после вызова
>   там мусор (стенд `harness_trash` это гарантирует).
> * **Не выставили `al` перед `printf`** — с `double` напечатается мусор.
> * **Седьмой аргумент по `[rsp + 8]` после `push`** — смещение изменилось.
> * **Компаратор через вычитание** — переполнение при больших числах.
> * **Функция C3 без `@export`** — `undefined reference`.

## Как это связано с упражнениями

* **`a0501` stack_args** — сумма с весами шести регистровых аргументов,
  `a + g*h` для восьми `long` и `g + h` для восьми `int`. Разделы 2.1 и
  2.3. Нарисуйте стек на входе (адрес возврата, 7-й, 8-й). Для `int` —
  читайте 4 байта. Для весов пригодятся `lea`/`imul` из главы 04.
* **`a0502` callee_saved** — функции считают верно, но портят `rbx`,
  `r12`–`r15`. Раздел 3. Два пути: сохранить/восстановить (3.2) или
  обойтись volatile-регистрами — подойдёт любой. Стенд проверяет
  канарейки (3.3).
* **`a0503` call_c3** — цикл, вызывающий `c3_weight` для каждого
  элемента. Разделы 3, 4, 6.1 (образец с трассировкой) и 9 (шаблон).
  Выпишите, что должно пережить `call` (их четыре), посчитайте `push`
  и выравнивание. Не забудьте случай `n = 0`.
* **`a0504` libc** — `snprintf` с `double` и `strlen(a) + strlen(b)`.
  Разделы 4 и 7. В первой функции не хватает двух вещей (`al` и
  выравнивание); во второй помните, что после первого `strlen` второй
  указатель в `rsi` уже испорчен, а первый результат нужно где-то
  сохранить.
* **`a0505` apply** — `a[i] = f(a[i])` и свёртка `acc = f(acc, a[i])`
  через указатель на функцию. Разделы 3, 4, 8 и 9. Посчитайте значения,
  переживающие вызов (в шапке: четыре и пять) — от этого зависит,
  нужен ли `sub rsp, 8`. Аргументы и результат колбэков — `int`.
* **`a0506` qsort** — компаратор по убыванию и вызов `qsort`. Разделы 7
  и 8 (особенно абзац про опасность вычитания). Компаратор — листовая
  функция, ему выравнивание не нужно; `asm_sort_desc` вызывает `qsort`
  — ему нужно. Какой аргумент `qsort` — адрес компаратора?

## Словарик

| Термин | Простыми словами |
|---|---|
| **ABI / System V AMD64 ABI** | правила вызова функций на уровне машинного кода в Linux/macOS |
| **`push` / `pop`** | положить на стек (`rsp -= 8`) / снять со стека (`rsp += 8`) |
| **адрес возврата** | куда вернуться после функции; кладёт `call`, снимает `ret` |
| **caller / callee** | вызывающий / вызываемый |
| **caller-saved (volatile, scratch)** | `rax, rcx, rdx, rsi, rdi, r8–r11`: портятся любым `call` |
| **callee-saved (non-volatile)** | `rbx, rbp, r12–r15`: функция обязана вернуть их как было |
| **листовая функция** | функция, которая никого не вызывает |
| **пролог / эпилог** | начало функции (сохранить регистры, выделить стек) / конец (вернуть всё) |
| **выравнивание стека** | `rsp` кратен 16 перед каждым `call` |
| **`≡ 8 (mod 16)`** | остаток 8 при делении на 16; последняя hex-цифра — 8 |
| **красная зона** | 128 байт под `rsp`, которые листовая функция может использовать без `sub rsp` |
| **канарейка** | известное значение для проверки, не испортили ли его |
| **вариадическая функция** | функция с `...`; ждёт в `al` число xmm-аргументов |
| **PLT** | таблица трамплинов для вызова функций из разделяемых библиотек |
| **`@export`** | атрибут C3: дать функции простое «сишное» имя |
| **колбэк** | функция, переданная другой функции для вызова |
| **косвенный вызов** | `call` по адресу из регистра или памяти |
| **хвостовой вызов** | `call g; ret` заменён на `jmp g` |
| **shadow space** | 32 байта, которые резервирует вызывающий в Windows x64 |
