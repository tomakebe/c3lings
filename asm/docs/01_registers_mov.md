# Глава 01. Регистры, `mov` и первая функция

В этой главе мы напишем первые функции на ассемблере и разберёмся с
самой частой инструкцией x86 — `mov`. Звучит скромно, но именно здесь
прячется половина ошибок начинающих: ширина регистров, знаковое
расширение, константы, которые «не влезают».

Упражнения: `a0101`–`a0105`.

## 1. Функция — это метка и `ret`

С точки зрения процессора «функции» не существует. Есть адрес, на
который делают `call`, и инструкция `ret`, которая возвращает управление.
Всё остальное — договорённость (ABI):

* аргументы-целые лежат в `rdi`, `rsi`, `rdx`, `rcx`, `r8`, `r9`
  (по порядку);
* целый результат возвращается в `rax` (или его части: `eax` для `int`,
  `al` для `bool`/`char`);
* регистры `rax`, `rcx`, `rdx`, `rsi`, `rdi`, `r8`–`r11` можно портить
  свободно; остальные — нельзя (подробно — глава 05).

Минимальная функция `int answer() { return 42; }`:

```asm
    .globl asm_answer
asm_answer:
    mov eax, 42
    ret
```

Функция `long second(long a, long b) { return b; }`:

```asm
asm_second:
    mov rax, rsi
    ret
```

Мнемоника для порядка аргументов: **D**iane's **S**ilk **D**ress
**C**osts **$8 9** — rDi, rSi, rDx, rCx, r8, r9.

## 2. `mov` и его семейство

| Инструкция | Действие | Пример |
|---|---|---|
| `mov dst, src` | копировать | `mov rax, rdi`, `mov eax, 5`, `mov rax, [rdi]` |
| `movabs reg64, imm64` | 64-битная константа | `movabs rax, 0x123456789ABCDEF0` |
| `movzx dst, src` | копировать с дополнением нулями | `movzx eax, dil`, `movzx eax, word ptr [rdi]` |
| `movsx dst, src` | копировать со знаковым расширением | `movsx rax, dil`, `movsx eax, si` |
| `movsxd dst, src32` | знаковое расширение 32 → 64 | `movsxd rax, edi` |
| `xchg a, b` | обменять | `xchg rax, rdx` |
| `cdqe` | `rax = (long)eax` | эквивалент `movsxd rax, eax` |

Ограничения `mov`:

* операнды одного размера: `mov rax, edi` — ошибка;
* нельзя «память → память»: `mov [rdi], [rsi]` — ошибка, только через регистр;
* `mov` **не меняет флаги** — его можно ставить между сравнением и переходом;
* непосредственная константа в большинстве форм — до 32 бит со знаком.

## 3. Ширина регистров и правила записи

Каждый регистр общего назначения доступен «окнами»:

```
 63                              31              15       7      0
 +-------------------------------+---------------+--------+------+
 |                              rax                              |
 |                               |      eax                      |
 |                               |               |   ax          |
 |                               |               |   ah   |  al  |
 +-------------------------------+---------------+--------+------+
```

Правило, которое нужно выучить наизусть:

* **запись в 32-битную часть обнуляет старшие 32 бита**;
* **запись в 8- или 16-битную часть сохраняет остальные биты**.

```asm
mov rax, -1        # rax = 0xFFFFFFFFFFFFFFFF
mov al, 0          # rax = 0xFFFFFFFFFFFFFF00
mov ax, 0          # rax = 0xFFFFFFFFFFFF0000
mov eax, 0         # rax = 0x0000000000000000
```

Почему так странно? В x86-64 запись в `eax` специально сделали
обнуляющей: иначе каждая 32-битная операция зависела бы от старого
значения `rax`, и процессору пришлось бы «склеивать» части. Для 8/16
бит поведение унаследовано от 8086 и 386, и его не тронули ради
совместимости. Следствие: компиляторы стараются писать в 32-битные
регистры (`xor eax, eax`, `mov eax, 1`), а частичные записи
(`mov al, ...`) обычно делают через `movzx`.

### Регистры `ah`, `bh`, `ch`, `dh`

Биты 8–15 четырёх «старых» регистров доступны отдельно. Ограничение:
их нельзя использовать в одной инструкции с регистром, которому нужен
REX-префикс (`r8`–`r15`, `sil`, `dil`, `spl`, `bpl`) — дело в
кодировке: с REX те же номера означают `spl`, `bpl`, `sil`, `dil`.

```
mov ah, sil
Error: can't encode register 'ah' in an instruction requiring REX prefix
```

В современном коде `ah` почти не встречается — но в упражнении `a0105`
он пригодится.

## 4. Расширение: zero и sign

Когда маленькое значение надо положить в большой регистр, возникает
вопрос: чем заполнить старшие биты?

| Исходный тип | Цель | Инструкция | Пример: байт `0x88` |
|---|---|---|---|
| `char` (u8) | `int`/`long` | `movzx eax, dil` | `0x00000088` = 136 |
| `ichar` (i8) | `long` | `movsx rax, dil` | `0xFFFFFFFFFFFFFF88` = −120 |
| `ushort` | `uint` | `movzx eax, di` | |
| `short` | `int` | `movsx eax, di` | |
| `uint` | `ulong` | `mov eax, edi` | (обнуление «бесплатно») |
| `int` | `long` | `movsxd rax, edi` | |

Заметьте: отдельной инструкции «`movzx` 32 → 64» нет — её роль играет
обычный `mov eax, edi`.

### Ловушка ABI: мусор в старших битах аргументов

Если аргумент имеет тип `int`, вызывающий кладёт его в `edi`. Что в
старших 32 битах `rdi` — **не определено**. Там может оказаться ноль,
может — мусор от прошлых вычислений. Знакового расширения там точно нет.
Поэтому:

```asm
# long widen(int x)
widen:
    mov rax, rdi       # НЕВЕРНО: для x = -5 вернёт 0x00000000FFFFFFFB
    movsxd rax, edi    # верно
    ret
```

То же для `char`/`short`: в `dil` значимы только 8 бит.

(Любопытная деталь: компиляторы на LLVM — clang и c3c — при вызове
расширяют `char`/`short` до 32 бит и даже полагаются на это в
вызываемой функции: `fn long f(ichar c) => c;` c3c компилирует в
`movsxd rax, edi`. Это неофициальное соглашение, документ ABI его не
требует, а gcc ему не следует. Полагаться на старшие биты 8- и
16-битных аргументов в своём коде не стоит, а 32-битных — тем более.)

## 5. Константы

Непосредственные операнды:

```
b8 ff ff ff ff          mov eax, -1     # eax = 0xFFFFFFFF, rax = 0x00000000FFFFFFFF
48 c7 c0 ff ff ff ff    mov rax, -1     # imm32, знаково расширенный: rax = -1
48 b8 ff ff ff ff 00 00 00 00   movabs rax, 0xffffffff
```

* `mov r64, imm32` — константа **знаково** расширяется до 64 бит;
* `mov r32, imm32` — константа пишется в 32-битную часть, верх **обнуляется**;
* `movabs r64, imm64` — единственная форма с полной 64-битной константой
  (10 байт). GNU as сам выбирает её, если вы пишете `mov rax, большое_число`.

Отсюда классический сюрприз: `mov eax, -1` и `mov rax, -1` — разные
значения `rax`. Упражнение `a0104` целиком об этом.

### Идиома `xor eax, eax`

Обнулить регистр можно `mov eax, 0` (5 байт), но компиляторы всегда
пишут `xor eax, eax` (2 байта). Процессор распознаёт её как «обнуление»
(zeroing idiom): она не зависит от старого значения и обрабатывается на
этапе переименования регистров. Единственный нюанс — `xor` меняет флаги,
так что между `cmp` и `jcc` её ставить нельзя.

Обратите внимание: `xor eax, eax`, а не `xor rax, rax` — результат тот же
(запись в 32 бита обнуляет верх), а байт REX не нужен.

### Разбор: трассировка по шагам

Чтобы почувствовать правила записи, проследим значение `rax` в
небольшой функции `ulong demo(ulong x)` при `x = 0x1122334455667788`
(`rdi = x`, `rax` на входе — мусор, скажем `0xAAAAAAAAAAAAAAAA`):

| Инструкция | `rax` после |
|---|---|
| `mov al, dil` | `0xAAAAAAAAAAAAAA88` — изменился только младший байт |
| `movzx eax, al` | `0x0000000000000088` — расширение нулями + обнуление верха |
| `mov ah, al` | `0x0000000000008888` — второй байт |
| `movsx rax, ax` | `0xFFFFFFFFFFFF8888` — бит 15 был 1, знак размножился |
| `mov eax, eax` | `0x00000000FFFF8888` — «пустая» инструкция, обнулившая верх! |
| `movabs rax, 0x7FFFFFFFFFFFFFFF` | `0x7FFFFFFFFFFFFFFF` |
| `xor eax, eax` | `0x0000000000000000` |

Обратите внимание на `mov eax, eax`: копирование регистра в самого себя
— не пустая операция, а идиома «обнулить старшие 32 бита». Компиляторы
используют её, когда нужно превратить `uint` в `ulong`.

Эту таблицу легко проверить самостоятельно: соберите любое упражнение,
поставьте в gdb точку останова на функции и выполняйте `stepi`,
печатая `p/x $rax` после каждой инструкции.

## 6. Как это делает компилятор

Напишите в C3:

```c3
fn long widen(int x) @export("widen") => x;
fn ulong low8(ulong x) @export("low8") => x & 0xFF;
fn long minus_one() @export("minus_one") => -1;
```

и соберите `c3c compile-only --emit-asm -O2 file.c3`. Вы увидите (в AT&T,
переведено в Intel):

```asm
widen:      movsxd rax, edi
            ret
low8:       movzx eax, dil
            ret
minus_one:  mov rax, -1
            ret
```

Ровно то, что мы делаем руками. Хорошая привычка в этом треке: решив
упражнение, посмотрите, как ту же функцию пишет компилятор, — на `-O0` и
на `-O2`.

## 7. Проверяем руками в gdb

```
./c3lings run a0103          # собрать (упадёт — не страшно)
gdb .build/a0103_widths
(gdb) set disassembly-flavor intel
(gdb) break asm_sext8
(gdb) run
(gdb) p/x $rdi
(gdb) stepi
(gdb) p/x $rax
(gdb) p $rax                  # десятично, со знаком
```

`p/x $al`, `p $eax`, `p/t $dil` (в двоичном виде) — gdb понимает имена
частичных регистров.

## 8. Подводные камни

* **`mov eax, X` для 64-битного результата.** Отрезает или портит
  старшую половину. Смотрите на тип в `extern fn` драйвера.
* **`mov rax, rdi` для `int`-аргумента.** Старшие биты `rdi` — мусор.
* **`mov al, ...` и затем использование `eax`/`rax`.** Верхние биты —
  старые. Используйте `movzx`.
* **`setcc al` без `movzx`** — та же проблема, увидим в главе 02.
* **`mov [rdi], 5`** — ассемблер не знает размер. Нужно
  `mov dword ptr [rdi], 5` (глава 04).
* **`mov rax, 0x80000000`** — это положительное число 2³¹, которое не
  влезает в imm32 со знаком; GNU as молча выберет 10-байтовый `movabs`
  (короче было бы `mov eax, 0x80000000` — результат тот же). А вот
  `add rax, 0x80000000` уже не ассемблируется (`operand type mismatch`) —
  у `add` нет 64-битной константы, нужен промежуточный регистр.

## Вопросы для самопроверки

1. В каком регистре приходит 5-й целочисленный аргумент? А 7-й?
2. Чему равен `rax` после `mov rax, 0x1122334455667788` и `mov ax, 0`?
   А после `mov eax, 0`?
3. Какой инструкцией превратить `short` из `si` в `long` в `rax`?
4. Почему `xor eax, eax` лучше, чем `mov rax, 0`? В какой ситуации её
   нельзя использовать?
5. Сколько байт занимает `movabs`? Почему 64-битные константы — редкость
   в коде?
6. Функция объявлена `extern fn long f(int x)`. Чем плох `lea rax, [rdi + 1]`?
7. Почему `mov ah, r8b` не ассемблируется?
