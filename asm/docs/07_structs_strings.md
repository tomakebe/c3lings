# Глава 07. Структуры, указатели, строки и строковые инструкции

Последняя глава первой половины трека собирает всё вместе: память,
адресацию, циклы и соглашение о вызовах. Мы посмотрим, как выглядят в
памяти структуры (и откуда в них берутся «дырки»), как обходить связные
списки, как работать с C-строками и что такое «строковые инструкции»
x86 — `rep movsb`, `rep stosb`, `repne scasb`, — которые живут в
процессоре с 1978 года и до сих пор используются в `memcpy`.

Упражнения: `a0701`–`a0706`.

## 1. Раскладка структур

Для процессора структура — кусок памяти, а поле — смещение. Смещения
вычисляются по правилам ABI (у C3 они те же, что у C):

1. Поля располагаются **в порядке объявления**.
2. Каждое поле выравнивается по своему требованию: `char` — 1, `short` —
   2, `int`/`float` — 4, `long`/`double`/указатель — 8, вложенная
   структура — по самому строгому из её полей.
3. Перед полем вставляется **padding**, чтобы смещение было кратно
   выравниванию.
4. Размер структуры округляется вверх до кратного её выравниванию —
   чтобы в массиве каждый элемент тоже был выровнен (хвостовой padding).

Пример:

```c3
struct Rec { char tag; long value; short count; }
```

| Смещение | Размер | Поле |
|---|---|---|
| 0 | 1 | `tag` |
| 1 | 7 | padding |
| 8 | 8 | `value` |
| 16 | 2 | `count` |
| 18 | 6 | хвостовой padding |
| | **24** | `Rec::size` |

Переставьте поля по убыванию размера — `long value; short count; char
tag;` — и получится 16 байт. В движке, где таких структур миллионы, это
треть памяти и кеша. Правило: **крупные поля — первыми**.

Проверить раскладку из C3 можно рефлексией:

```c3
io::printfn("%d %d", Rec::size, Rec::members[1].offset);   // 24 8
```

### Смещения в ассемблере

В GNU as удобно дать смещениям имена:

```asm
    .set REC_TAG, 0
    .set REC_VALUE, 8
    .set REC_COUNT, 16
    .set REC_SIZE, 24

    movzx eax, byte ptr [rdi + REC_TAG]
    add rax, [rdi + REC_VALUE]
    movsx rcx, word ptr [rdi + REC_COUNT]
```

Компилятор за вас эти константы не пересчитает: поменяли структуру в
C3 — поменяйте `.set`. Это главный источник ошибок на стыке ассемблера и
языка высокого уровня. Хорошая практика — проверять раскладку в драйвере
(`assert(Rec::members[1].offset == 8)`), как делает `a0701`.

### Массив структур

Элемент `i` — по адресу `base + i * sizeof`. Если размер не 1/2/4/8,
индекс домножают отдельно (`lea rax, [rcx + rcx*2]` для `*3`, затем
`[rdi + rax*8]` для `*24`) или просто сдвигают указатель на `sizeof`
каждую итерацию.

## 2. Указатели и связные структуры

Указатель — 8-байтовое число; `null` — 0. «Разыменовать поле» —
обращение со смещением:

```asm
    mov rax, [rdi + 8]          # p->next
    test rax, rax
    jz .Lend                    # next == null
```

Обход связного списка:

```asm
.Lloop:
    test rdi, rdi
    jz .Lend
    add rax, [rdi + 16]         # sum += p->payload
    mov rdi, [rdi + 8]          # p = p->next
    jmp .Lloop
```

Заметьте зависимость: адрес следующей загрузки — результат предыдущей.
Процессор не может начать читать `p->next->next`, пока не дочитал
`p->next`. Каждый шаг — полная задержка памяти (4 такта из L1, ~100+ из
RAM). Именно поэтому в движках связные списки не любят, а массивы любят
(глава 14 и трек 3).

Разворот списка на месте — три указателя (`prev`, `cur`, `next`) в
регистрах и две операции с памятью на узел.

## 3. C-строки и срезы

**C-строка** (`ZString` в C3, `char*` в C) — указатель на байты,
заканчивающиеся нулём. Длина не хранится; чтобы её узнать, нужно
пройти до нуля (`strlen` — O(n)).

**Срез** C3 (`String` = `char[]`) — пара «указатель + длина», 16 байт.
При передаче в функцию по System V он раскладывается на два регистра:
`fn void f(String s)` получит `s.ptr` в `rdi`, `s.len` в `rsi`. Длина
бесплатна, нулевого байта может не быть.

Строковые константы в ассемблере:

```asm
    .section .rodata
hello:  .asciz "hello"          # 6 байт: h e l l o \0
raw:    .ascii "abc"            # 3 байта, без нуля
    .text
    lea rdi, [rip + hello]
```

Символьные константы GNU as понимает: `cmp al, 'a'`, `mov byte ptr
[rdi], ' '`.

### Побайтовая обработка

```asm
    movzx ecx, byte ptr [rdi]   # прочитать байт (без мусора сверху)
    test ecx, ecx
    jz .Lend                    # конец строки
```

Проверка «строчная латинская буква» одним сравнением (приём из главы 03):

```asm
    lea edx, [rcx - 'a']
    cmp edx, 'z' - 'a'          # 25
    ja .Lnot_lower              # беззнаково
    sub byte ptr [rdi], 32      # 'a' - 'A' == 32
```

## 4. Строковые инструкции

Набор инструкций с неявными операндами: источник — `[rsi]`, приёмник —
`[rdi]`, счётчик — `rcx`, значение — `al`/`ax`/`eax`/`rax`. После
каждой операции `rsi`/`rdi` сдвигаются на размер элемента (вперёд при
DF = 0, назад при DF = 1).

| Инструкция | Действие (для байтов) | Варианты |
|---|---|---|
| `movsb` | `[rdi] = [rsi]`; rsi++, rdi++ | `movsw`, `movsd`, `movsq` |
| `stosb` | `[rdi] = al`; rdi++ | `stosw`, `stosd`, `stosq` |
| `lodsb` | `al = [rsi]`; rsi++ | `lodsw`, `lodsd`, `lodsq` |
| `scasb` | сравнить `al` с `[rdi]`; rdi++ | `scasw`, `scasd`, `scasq` |
| `cmpsb` | сравнить `[rsi]` с `[rdi]`; rsi++, rdi++ | `cmpsw`, `cmpsd`, `cmpsq` |

(`movsd` здесь — «move string dword». Одноимённая SSE-инструкция
`movsd xmm0, xmm1` — совсем другая, ассемблер различает их по операндам.)

Префиксы повторения:

| Префикс | Повторять, пока | Используется с |
|---|---|---|
| `rep` | `rcx != 0` | `movs`, `stos`, `lods` |
| `repe` / `repz` | `rcx != 0` и ZF = 1 (равны) | `scas`, `cmps` |
| `repne` / `repnz` | `rcx != 0` и ZF = 0 (не равны) | `scas`, `cmps` |

Каждое повторение уменьшает `rcx`.

### memcpy и memset

System V удачно совпадает со строковыми инструкциями: `rdi` — первый
аргумент (dst), `rsi` — второй (src).

```asm
# void* memcpy(void* dst, void* src, usz n)
asm_memcpy:
    mov rax, rdi        # вернуть dst — до того, как rep его сдвинет
    mov rcx, rdx
    rep movsb
    ret

# void* memset(void* dst, int c, usz n)
asm_memset:
    mov r8, rdi
    mov eax, esi        # байт для заполнения — в al
    mov rcx, rdx
    rep stosb
    mov rax, r8
    ret
```

### strlen через `repne scasb`

```asm
    xor eax, eax        # al = 0 — ищем нулевой байт
    mov rcx, -1         # «без ограничения»
    repne scasb         # идём, пока [rdi] != 0
    not rcx             # rcx = число проверенных байт (включая ноль)
    dec rcx             # без нуля
    mov rax, rcx
```

Арифметика: стартовали с `rcx = -1`, проверили `k` байт, стало
`-1 - k`; `not` даёт `k`; минус завершающий ноль. После `repne scasb`
флаг ZF говорит, чем закончилось: ZF = 1 — нашли, ZF = 0 — исчерпали
`rcx` (так `memchr` отличает «не найдено»).

### Флаг направления DF

`std` ставит DF = 1 (адреса убывают), `cld` — сбрасывает. ABI требует
DF = 0 при входе в функцию и при выходе. Значит, `cld` перед `rep movsb`
писать не обязательно — но если вы использовали `std` (например, для
`memmove` с перекрытием назад), обязательно верните `cld`, иначе
сломаете следующую `memcpy` в libc.

### Быстро ли это?

Зависит от инструкции:

* **`rep movsb` / `rep stosb`** на процессорах с флагом **ERMSB**
  (Enhanced REP MOVSB, Intel с Ivy Bridge, AMD Zen 3+) и **FSRM** (Fast
  Short REP MOV, Ice Lake+) — быстрые: микрокод копирует целыми
  кеш-линиями. glibc использует `rep movsb` для больших копий (от
  нескольких килобайт). На малых размерах есть фиксированная стоимость
  запуска в десятки тактов — там выигрывают обычные `mov` векторными
  регистрами.
* **`repne scasb`, `repe cmpsb`, `lods`** — медленные, ~1 байт за такт
  или хуже. Реальные `strlen`/`memchr`/`memcmp` в glibc используют AVX2
  (32 байта за инструкцию, глава 10).

Проверить флаги вашего CPU: `grep -o -w 'erms\|fsrm' /proc/cpuinfo | sort -u`.

## 5. Как это делает компилятор

Копирование структуры в 64 байта (`*d = *s;`) c3c `-O2` развернул в
восемь векторных `mov` — без всяких циклов:

```asm
copy:
    vmovups xmm0, [rsi]
    vmovups xmm1, [rsi + 0x10]
    vmovups xmm2, [rsi + 0x20]
    vmovups xmm3, [rsi + 0x30]
    vmovups [rdi + 0x10], xmm1
    vmovups [rdi], xmm0
    vmovups [rdi + 0x30], xmm3
    vmovups [rdi + 0x20], xmm2
    ret
```

Цикл обнуления `for (i = 0; i < n; i++) d[i] = 0;` компилятор
**распознал** и заменил вызовом `memset` (точнее, хвостовым `jmp memset`).
А побайтовое копирование в цикле — превратил в векторизованный цикл по
128 байт с проверкой перекрытия буферов. Строковые инструкции
компиляторы сами генерируют редко (иногда `rep stosq` для обнуления
больших локальных массивов, `rep movsq` при `-Os`).

## 6. Подводные камни

* **Смещения без учёта padding.** `value` по смещению 1 вместо 8.
* **Шаг массива структур — без хвостового padding.** `sizeof` = 24, а не 18.
* **Размер поля при чтении.** `short` — `movsx ..., word ptr`, а не `mov eax`.
* **Байт без `movzx`.** Мусор в старших битах при сравнении или индексации.
* **Off-by-one в strlen.** Посчитали завершающий ноль или пропустили
  первый символ.
* **`rep movsb` без `mov rcx, n`.** В `rcx` — 4-й аргумент или мусор,
  копирование непредсказуемой длины (часто — segfault).
* **`stosb` пишет `al`, а там младший байт dst.** Не забудьте `mov eax, esi`.
* **Не вернули dst из memcpy/memset.** `rdi` уже сдвинут — сохраните
  заранее.
* **Оставили DF = 1.** Ломается любой следующий код со строковыми
  инструкциями.
* **Разворот списка — потеряли хвост.** Прочитайте `next` до того, как
  перезапишете `cur->next`.
